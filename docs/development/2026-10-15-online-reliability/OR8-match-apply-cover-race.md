# 标签匹配封面并发保护

2026-10-16。本文记录 RR16 中标签匹配与同曲本地封面写入交错时的受控修复。它是离线集成证据，不表示 OR8 整体验收完成。

## 触发顺序

1. 标签匹配开始时，索引记录没有本地封面，因此允许抓取候选封面。
2. 远程请求仍在等待时，用户已选的封面先通过同曲写入队列落盘并更新曲目索引。
3. 旧实现将抓取到的封面直接提交，没有在队列内按最新索引重新执行“默认不覆盖”的判断。

侧车写入可能先把 `sidecar` 记录合入索引，而 `coverPath` 会在后续扫描中补全，因此判定同时看本地 `embedded`、`sidecar`、`user` 来源。仅有在线 `remote` 来源不会被当成本地封面。

## 修复

- `IPC.matchApply` 仍在抓取前检查当前状态，已有封面时不会多发请求。
- `commitAssetWrite` 在同曲路径队列中读取最新曲目，再按 `overwriteCover` 决定是否把远程 `cover` 留在写入补丁中。
- 默认策略丢弃过期的远程封面字段，但标题、艺人和歌词等其他字段继续提交。被移除的封面也不会取得待写入项的清理权限。
- 显式 `overwriteCover: true` 保持原有覆盖行为。

## 验证

- RED 阶段两项并发场景都因缺少提交边界策略而失败；实现后3/3通过。
- `npm run typecheck` 通过。
- `npm run verify` 退出码0：生产构建通过，90/90离线套件通过，内置平台门禁5/5通过。
- `git diff --check` 通过。
- 独立只读复核未发现P1/P2；根据复核补充 `embedded` 与 `user` 来源分类断言，目标回归仍为3/3通过。
