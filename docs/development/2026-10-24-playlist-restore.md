# JSON 歌单备份导入恢复（2026-10-24）

用户已确认[恢复为新歌单设计](../superpowers/specs/2026-10-24-playlist-restore-design.md)，承接[信息导出](2026-10-24-playlist-filter-backup.md)。

## 使用和边界

歌单管理 → 从 JSON 恢复 → 原生选择单个 JSON → 查看创建时间、名称及歌单/曲目数量 → 确认恢复为新歌单。

每个歌单使用新 UUID 追加，通常名称加恢复后缀；原名超过4092字符时保留原名，避免超过导出4096字符限制，不截断。收藏和默认列表恢复为普通副本，原有内容和当前队列保持原样。同名分别保留；重复导入创建另一组副本，不合并覆盖。

仅支持本应用 kind=jj-music-playlists、version=1、single/all 格式，上限20MiB原文件和实际读取字节、1000歌单、50000曲目。缺字段、无效UTF-8、未知版本、类型错误、重复歌单ID或重复完整曲目身份整体拒绝；BOM可接受，空备份提示无需恢复。白名单不含脚本、临时播放URL、任意providerData、图片/歌词文件和播放器设置。

本地路径只保留引用，不读取个人音乐、不扫描或写入音频；缺失时使用现有重新定位功能。在线仍需现有音源解析。信息恢复不是全资料目录恢复，也不是实际平台音频/听感验收。

## 一致性与生命周期

主进程打开原生选中的普通JSON一次，stat及分块读取均有上限，finally关闭句柄；界面不提交路径/原始曲目。预览保留一份克隆后的权威快照，10分钟TTL、一次性令牌、容量1。取消/离页/迟到结果释放所属令牌。确认使用预览数据，原文件后来变化不替换本次内容。失败需重新预览。

全部新歌单进入现有同一持久化队列，一次原子保存；失败整批回滚。保存成功但界面刷新失败明确提示已恢复、无需重复恢复。恢复成功清空管理页名称筛选。

## 审查与修复

独立最终审查复现：恢复允许相同原始ID的本地/在线条目，但旧排序Map和移除/复制只按原始ID，可能丢曲目。已RED/GREEN修复完整身份链路：详情重排/移除传完整key与显式模式，旧调用歧义则拒绝；TrackList行key/选择/菜单、复制去重、收藏及徽标均按完整身份；队列追加、插播和移除也区分。IPC严格校验模式、数量和长度。未重写播放器其余异步身份架构，不宣称全播放器身份改造。

另已先复现4096字符名称恢复后无法再次导出的边界，再保留原名解决；预览说明该例外。审查员复核修复链路通过，无新增P1/P2。
