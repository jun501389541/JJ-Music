# 源失败证据保留计划

> 使用 executing-plans 顺序实施，末尾一次独立只读复核；当前工作区保存基线后继续，不提交推送。

**Goal:** 修复真实检查暴露的宿主超时在错误汇总后变成unknown。
**Spec:** ../specs/2026-10-15-online-reliability-design.md，OR1/OR5/OR7/OR8，结构化错误与分级诊断。
**Architecture:** SourceEngine两处汇总保留本次尝试规范化失败；单一或一致code/scope保留，混合为unknown。HTTP状态只在一致时保留，429已知等待取最大；不同源身份不合并为某一源。保留既有UI详情文案，failure.message仍为受控摘要。

- [x] 保存diff/untracked哈希；注入宿主响应回归RED：超时、网络、429/冷却、质量缺失、混合失败与最后成功、歌词汇总。
- [x] 实现错误证据汇总与完整安全诊断码白名单，局部GREEN；不改候选/音质/取消/重试顺序。
- [x] 独立只读复核；完整verify；有必要时用已授权HYW单平台单样本观察正式报告，不制造超时或限流。
- [x] 保留真实失败与历史结果，差异保护、交接记录和增量索引。

Review focus: 混合失败不能借首个错误伪造结论；部分HTTP/等待证据不能假装全部相同；详情文案中的私有错误不进入白名单报告；成功的下一候选仍返回；未执行平台和无目标档位与服务故障区分。
