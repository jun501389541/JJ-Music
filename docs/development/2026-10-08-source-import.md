# 音源导入修订与首次导入刷新修复

## 用户确认

2026-10-08 用户要求删除音源管理空状态中的 LX `user_api.json` 路径提示，并移除对应的配置导入功能。随后反馈首次选择本地 `.js` 文件后没有出现音源卡片。

## 修改

- 删除音源管理与发现音乐页面的配置导入提示，同步 README、架构说明和 PRODUCT_RULES 的 V25。
- 文件选择与拖入入口只接收 `.js`、`.txt` 脚本；公共导入解析器拒绝 JSON 配置、JSON 数组及其 `gz_` 编码内容，覆盖粘贴和链接入口。
- 移除 `importLxFile`；保留单脚本导入、压缩脚本解码，以及已有音源的内部 JSON 存储和读取。
- 修复导入报错后的列表同步：主进程可能先保存脚本并停用/隔离，再返回校验错误；此前界面仅在成功时刷新，导致首个音源仍显示为空列表。文件、粘贴与链接导入现在在报错后也刷新，并保留原始错误。

## 验证

- 首次导入刷新回归先复现三个入口的空列表问题；修复后七项回归通过，包括刷新失败时保留原始错误和取消文件选择。
- 原 LX 配置导入套件按用户取消的功能替换为单脚本导入套件；三个案例验证明文/编码脚本、拒绝配置且不修改音源，以及读取已有资料。首轮测试夹具头部格式不正确，修正为正常多行头部后通过。E0 记录的历史基线失败保持不变。
