# 稳定性与本地媒体优化

本轮修复播放生命周期、并发保存和歌词状态，并更新本地媒体访问与测试方式。

## 行为变化

- 自然播放结束会正确进入下一首；单曲循环自动重播，手动“下一首”仍会切换。
- 停止、清空队列和新选择会使旧播放与歌词请求失效；旧请求不能重新开始播放或覆盖新歌词。
- 加载中的播放按钮可取消选择；停止后再次播放会重新加载当前曲目。
- 手动导入、编辑歌词和写入标签后，重新按本地侧车、内嵌标签、在线匹配的优先级读取。
- 在线地址缓存有效期为 5 分钟，上限 128 条。播放地址失败最多重新获取一次；再次失败停下并显示原因，避免无限跳歌。
- 跨平台备用音源只接受规范化标题、歌手一致且时长差不超过 5 秒的结果；缺少可靠时长时不自动切换，避免误播其他版本。
- JSON 按目标文件串行保存，入队前快照数据，并使用唯一临时文件。失败后后续保存仍可继续。
- 封面按图片内容 SHA-256 缓存。相同图片共用文件，更换封面会产生新 URL。索引版本升级为 3，首次启动在后台重新读取旧索引。
- 本地媒体只读取曲库目录、封面缓存和本次通过文件选择器选中的媒体文件。解析真实路径后检查访问范围，拒绝目录联接越界。
- Range 支持指定区间、开放结尾、末尾 N 字节；处理非法区间、HEAD 与空文件。协议拒绝非媒体扩展名，IPC 拒绝其他窗口与子框架来源。
- 所有界面共用媒体 URL 编码函数；协议测试直接导入生产模块。

## 验证

- `npm run verify`：类型检查、生产构建及 10/10 无头测试套件通过。
- `npm run test:online`：2/2 真实联网测试套件通过，覆盖搜索及元数据匹配。
- `npm run test:e2e`：30/30 检查通过；实际解码时钟推进、分析器非零频谱、拖动进度、暂停、歌词同步和 IPC 均正常。
- 新增或重写的播放、媒体协议和持久化回归测试：24 项通过。
- E2E 结束后恢复普通生产构建，运行时确认测试入口不可访问。
- `npm run dist` 成功，便携版与安装包均已更新。包内 28 个应用构建文件与生产输出逐字节一致；音源宿主正确解包，测试代码未打入发行包。
- 本机样本：1112 首曲目、1111 首带封面，共生成 934 个独立封面文件；一次增量重扫为 85 ms。该结果依赖本机数据与硬件，不是通用性能保证。

默认无头测试不请求外部音乐服务；真实联网验证单独运行并保留失败状态。歌词写入测试使用临时音频副本。

## 仍需独立处理的工作

- 第三方音源仍在具有当前用户权限的 Node 子进程中执行。本轮澄清了文档和界面的权限说明，没有实现操作系统级权限沙箱。
- 大曲库虚拟滚动、搜索索引、扫描并发与性能基准仍需后续实施。
- 旧封面缓存保留，避免破坏已保存歌单中的封面引用；未实现自动垃圾回收。
- 旧网络请求会被忽略，但底层 IPC 尚未提供取消网络请求的接口。
- IPC 增加了来源限制，尚未为所有参数建立统一运行时校验模型。

本轮已更新 `release/win-unpacked/JJ Music.exe` 与 `release/JJ Music-0.1.0-x64.exe`。今后修改源码仍需重新打包：`npm run pack` 生成便携版，`npm run dist` 生成安装包。
