# 本地缺失文件逐首重新定位

状态：用户已确认本功能、逐首手动选文件范围及本文具体行为，并明确要求实施。实现与验证结果见开发记录；本文描述产品设计，不替代实际验收证据。

## 目标与现状

用户移动音乐文件后，可以为原本地歌曲手动选择新文件，确认后继续使用原有收藏、歌单及播放记录。保持本地与在线来源独立，不自动改播在线同曲。

当前 LocalMusicInfo.id 来自 hashPath(path)，歌单、最近播放、LastSession 和历史队列分别保存歌曲对象。MusicLibrary 按路径建立索引；重新扫描可能移除缺失项。因此不能只修改播放器的 path，也不能依赖旧记录仍在曲库。

## 用户流程

1. 本地歌曲右键“文件”菜单增加“重新定位文件”；首版只处理当前一首。旧文件仍可访问时提示无需重新定位，不提供替换正常文件入口。
2. 主进程打开单文件音乐选择框，用户取消则保持原记录。权限错误与缺失分别提示，不将读取失败当成缺失自动替换。
3. 选中后显示旧、新路径及双方可用的标题、歌手、时长；明确提示由用户核对是否为同一录音。格式无效、不可读或新路径已属于另一首已索引歌曲时拒绝，避免自动合并收藏和队列。
4. 用户确认后修复关联，反馈成功；如果是当前歌曲则停止旧的播放尝试，保持原队列顺序和位置，不自动开始播放。取消确认不修改记录。

## 歌曲身份与资料

- 采用新路径生成的新 ID，与现有扫描规则一致；将旧本地 ID 和旧路径对应的引用迁移到新歌曲，不改其他本地条目或在线条目。
- 新文件重新读取标签、封面、歌词来源及音频属性；不把旧路径的侧车或嵌入资源来源冒充新文件已有内容，不写入音乐标签，不移动或删除音频。
- 保留收藏、各歌单中的位置、最近播放位置、当前队列索引与模式、历史队列顺序。历史队列仅修复对应本地引用，不改变其原有队列内容和顺序。LastSession 保留进度，恢复时按实际媒体时长约束。
- 旧曲库记录即便已被扫描删除，只要主进程仍能从歌单、收藏或已保存播放记录确认原条目，也允许重新定位。不能只信任渲染进程提交的任意路径。
- 新文件可位于原监视目录之外，作为用户明确选择的单文件导入；不自动扩大扫描目录。
- 待写入歌词/封面保留原资源，不自动写到新文件。成功提示存在此类条目时，须到现有待写入页面重新选择目标。旧下载记录保留原始下载路径，不能借重新定位让删除下载操作转而删除用户新选文件。

## 一致性与失败处理

选择阶段不修改用户数据。确认前复核旧记录、新文件及候选有效期；旧文件恢复可用、候选改变、条目被删除或目标已入库时拒绝提交并重新选择。

曲库、歌单及设置引用的变更由主进程统一协调；与扫描、标签写入、歌单变更及退出互斥或采用代次失效，阻止旧路径迟到结果回填。持久化跨多个文件，采用可恢复事务记录与幂等更新；写盘失败不反馈成功，不丢弃恢复信息，重启先完成恢复后开放受影响操作。不得回放旧完整快照覆盖其他用户修改。

## 不在首版范围

批量目录搜索、自动同曲匹配、在线替代、文件内容搬移、批量改名，以及自动合并已入库歌曲。

## 验收

- 实际临时音频移动后，选新文件并确认：曲库与收藏/歌单/最近播放/队列/LastSession 引用一致，重启后仍能读取；当前条目不意外自动播放。
- 取消选择、取消确认、旧文件仍存在、读取权限失败、非法音频、目标冲突、候选变更均保留原有数据。
- 旧索引已移除但歌单仍引用时可以恢复；扫描及标签读取迟到不会复活旧路径。
- 注入各持久化阶段失败与重启恢复，验证幂等、顺序保持、不覆盖并发修改。
- 现有待写入资源及下载记录不丢失、不被静默重定向；在线同 ID 不受影响。
- 使用 tools/build-test.mjs 和正式离线测试；独立隔离 Electron UI 走真实选择/预览/取消/确认与重启。真实音乐文件及日常 profile 不参与测试。
