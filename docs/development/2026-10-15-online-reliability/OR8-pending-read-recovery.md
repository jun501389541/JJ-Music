# OR8：待写入资料读取失败保护

日期：2026-10-16，对应 OR-10、RR08、RR16。接续容量和旧快照保护保留的首次读取损坏文件边界。

## 原因与修复

原实现把 readFile 异常和 parseJsonLoose 失败均当作空队列，并缓存这次“加载成功”；后续 add 会用空状态覆盖原文件。临时读取故障消失后，同一实例也不重新加载原选择。

现在只有 ENOENT 表示首次空资料。读取错误、JSON 语法错误、非兼容根结构均报告固定中文错误，保留原字节，不自动移动、备份、截断或删除文件。所有实际修改仍须通过 change 等待一次成功加载，因此读取失败时无法进入写入器。加载失败的 Promise 按引用清除，允许在同一个服务实例修复文件后重试；读取和验证完整成功后才发布两个状态表。

没有直接复用 readJsonFile：该通用函数在损坏文件备份失败后仍允许空状态回退，不满足这里“保留原字节且拒绝覆盖”的边界。本轮没有改它或其他资料存储。

主进程初始化改用 loadForStartup 隔离附属队列错误，只记录固定中文消息，继续创建播放器服务；它不缓存空状态，后续待写入读写仍拒绝并显示错误。设置页原有 refreshPending 会显示查询失败并禁用队列操作，不会把它显示成“没有等待写入的内容”；已静态核对该调用链，本轮没有声称完成损坏profile的实际UI启动验收。

## 验证

新增 pending-asset-read-recovery.test.mts，全部使用生成临时目录与生产打包模块，共10项：

- JSON截断、null根、entries非数组、不支持的对象结构、dismissed非数组：load/add/clear均拒绝，原文件字节和目录内容不变。
- 用非空目录模拟读取失败，首次load与并发add均拒绝，哨兵保留；恢复真实文件后同实例add保留原条目。
- 修复损坏JSON后同实例恢复原条目及丢弃指纹，再添加新条目，重启结果一致。
- 文件不存在仍可正常首次创建；BOM与旧裸数组继续兼容。
- 启动隔离函数返回，报告不含损坏原文；写操作仍被拒绝，修复后启动重试不再报警且原选择可读。

初始8项中6项缺陷回归先失败，另2项兼容检查通过；修复后新增10项与既有快照14项、容量9项共33/33通过。日志为 `.cache/pending-asset-read-red.log`、`.cache/pending-asset-read-green.log`。独立代码复核未发现本轮范围内的P1/P2阻断问题。

最终 `npm run verify` 退出0：类型检查、生产构建、88/88离线套件及5/5门禁通过，日志为 `.cache/pending-asset-read-verify.log`。`git diff --check` 通过；本轮jj-pending-read专用临时目录只读核对剩余0；GraphFlow已增量索引。没有提交或推送。

## 保留边界

后续生产界面补验（2026-10-17）：损坏资料下启动、错误反馈/按钮禁用、原字节保留，以及同实例修复后的队列显示与丢弃落盘，已由15项隔离Electron检查通过并查看截图。详见[界面验收记录](OR8-pending-ui.md)；不改写上文当时尚未UI验收的观察。

- 原文件留在原路径，需修复或还原后重试；本轮不猜测或恢复损坏内容，不自动覆盖为新的空队列。
- 保留兼容的逐条usable过滤策略，不宣称能恢复根结构合法但内部某条记录已损坏的数据。
- 单实例首次读取失败的保护不代表跨实例目录写入安全，也不监视已成功加载后外部对文件的修改。
- 原有容量、串行持久化、flush、快照CAS与原子丢弃语义保持。本轮未执行真实源、日常歌曲、人工听感、安装或发布。
