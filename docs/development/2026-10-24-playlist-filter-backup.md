# 歌单内查找与 JSON 信息备份（2026-10-24）

用户选择两项一起开发，依据[设计](../superpowers/specs/2026-10-24-playlist-filter-backup-design.md)和[计划](../superpowers/plans/2026-10-24-playlist-filter-backup.md)实施。

## 已实现

- 已保存歌单详情支持按歌名、歌手、专辑查找；NFKC、大小写归一、多词同时匹配，显示匹配数/总数。按歌单分别记住本次会话关键词，可清空及返回恢复。
- 筛选仅改变显示。点击歌曲按它在完整歌单的身份定位，继续使用完整队列；“播放全部”仍播放完整歌单。筛选时禁拖动排序；移除可见歌曲保留隐藏曲目的顺序和身份。
- 详情的“导出完整歌单”始终导出当前已保存完整歌单。管理页“备份全部歌单”包括收藏、默认列表、空歌单，不受名称筛选影响。确认范围后才打开原生保存对话框。
- 文件格式为 kind=jj-music-playlists、version=1，含创建时间、单个/全部范围，以及歌单 ID、名称、来源、来源歌单 ID、存储位置和顺序排列的曲目。曲目保留本地/在线身份、基础资料、本地绝对路径或已知平台原生标识、音质标识；同名歌单不合并。
- 仅导出字段白名单；不含音频、图片/歌词文件、临时播放地址、缓存资源、音源脚本、任意 providerData 或播放器设置。全部导出按歌单存储 position 排列，侧栏自定义顺序属于设置，不在文件内。
- 快照排在持久化操作队列中读取，不导出未提交/回滚状态。最多 1000 个歌单、50000 个曲目、20MiB UTF-8；超限或必要字段损坏明确失败，不截断。
- 保存位置只能来自主进程原生对话框，只接受 .json，使用原子写入；规范化真实父目录后拒绝写入当前应用资料目录（含目录联接别名）。取消不写入，失败清除临时文件并允许重试；同一时刻只允许一个导出。

## 范围边界
