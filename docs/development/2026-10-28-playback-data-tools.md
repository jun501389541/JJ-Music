# 播放数据备份恢复与书签总览

用户选择两项按顺序开发，并授权“按建议直接开发”；沿用当前隔离分支，保留此前未提交功能，不提交、推送或发布。[设计](../superpowers/specs/2026-10-28-playback-data-tools-design.md)与[计划](../superpowers/plans/2026-10-28-playback-data-tools.md)。

设置/数据新增四类播放数据JSON备份：歌词校准、续播、书签、累计及日期统计。主进程原生选择文件，64MiB总上限与各类别原容量限制；严格白名单剥离额外字段，导出拒绝资料目录及指向其内的目标。预览十分钟、一次令牌且不写盘；确认时重新判断缺失key，只补缺失整曲记录，已有书签整组保留、统计不相加。

四个现有文件分别串行原子写；不承诺跨文件全有或全无。中途失败如实显示完成类别，再选择原备份可补齐剩余；应答丢失重试不重复累计。当前统计覆盖起点不因补入旧日期而向前扩展，避免制造未知历史的零。坏文件保留，迁移与备份互斥，关闭前每类别再次检查可用性。备份只包含主进程已确认记录，界面会先尝试flush续播与统计，未确认尾段可能不包含。

时间点书签侧栏总览支持搜索、100条分页、重新匹配。只从当前音乐库、队列、最近播放和已存歌单按完整身份解析曲目，未匹配记录保留且禁播，不从书签字符串构造文件路径。当前曲跳转保持暂停；其他曲明确切换为独立单曲队列，先暂停加载实际媒体，再在所属尝试代次、用户toggle/seek代次、书签原值和实际时长均有效时同步定位起播；既有队列历史规则保留。
