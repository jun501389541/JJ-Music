# OR5 — 能力健康与播放恢复

实施及离线交付：2026-10-16。依据原设计 OR5 与 [实施计划](../../superpowers/plans/2026-10-16-online-reliability-or5.md)。OR6–OR8 继续待实施，真实服务与听感未验证。

## 健康策略

- 新 `CapabilityHealth` 只在内存保存最多 2000 个健康键。目录键为平台、能力、适配器修订；脚本另含稳定音源 ID、内容版本。无后台扫描或定时探测。
- 5 分钟窗口内连续 3 次可计数服务失败后等待 60 秒；半开失败延长到 120 秒，再到最多 300 秒。只在有效请求到达时放行一个探测，真实成功重置；取消释放许可但不证明恢复。
- 网络、超时和契约结构错误可计数；取消、本地缓存错误、未知失败、单资源访问拒绝、缺歌曲/档位和不支持能力不计服务失败。脚本返回空/空白 URL 属于档位不可用，不阻断下一档；未知脚本文案不猜成网络故障。
- 手动意图可跳过普通冷却，同一键至少间隔 30 秒；不能跳过在途探测、429 等待或源停用。显式再次播放错误条目会传递手动重试意图，自动恢复不会冒充手动操作。
- 429 首次响应就发布等待期，不等整段重试结束。重试所有者持有恢复许可，每次实际尝试前再检查最新等待期和代次；已准入请求也不能用较短的旧等待期绕过后来更长的限制。
- 目录、热词、歌单和普通平台资产在缓存 loader 内计数，缓存命中不进入健康层。脚本歌词/封面只由源引擎计数，资产层不另建聚合健康计数。部分歌单不证明完整恢复，也不能清除已观察到的等待。
- 源请求维持已有 20 秒上限与一次 429 重试所有权。LX 只传文本 `HTTP 429` 时保留既有 500ms 本地退避；这不是声称获得了服务器 Retry-After。结构化等待证据存在时服从该等待，其他目录未知等待使用健康层 60 秒保守等待。

## 地址与媒体恢复

- URL 缓存仍仅内存、最多 128 项，目标档与源身份约束保持。降档成功不缓存为下一次目标档成功；源变化事件清缓存并撤销正在解析的意图。
- IPC 提供宿主解析时间；URL 缓存同时校验墙钟与 `performance.now()` 单调期限，实际有效期至多 5 分钟。可选可信 `expiresAt` 使用提前 30 秒与 5 分钟的较短值。早于获取时间、无效时间或已到期结果不复用。
- LX 标准结果仅 URL 字符串，目前没有可信源站到期元数据；本期不解析签名查询参数猜到期时间。`expiresAt` 的合成测试验证宿主契约，不能据此声称真实源都提供了到期字段。
- 媒体错误区分取消、网络、解码、不支持和未知。主进程媒体代理只返回当前受控令牌的安全错误证据：本地令牌确实到期、来源变化、上游 403 或未知 404等，不暴露原始地址、头或错误。
- 取消不触发恢复；解码/不支持格式/访问拒绝不冒充 URL 过期。真实网络故障或受控令牌确实到期，可按原流程重新解析一次；普通 HTTP 403/404 不作为过期证据。
- 异步媒体诊断有短等待上限，返回后重新检查播放代次与原条目。自动恢复继续使用原截止时间，同时检查单调时钟；实际播放成功后发生错误也不另送一分钟。失败不自动跳过队列条目。
- 保留原条目身份、同版本录音匹配、严格逐档候选和绑定源规则；自动缓存/恢复不改收藏或已保存歌单。

“在线资料缓存”开关同时控制本期健康保护，设置描述已说明；关闭时清内存健康状态，保留基础播放与有界请求。清普通缓存不会让用户频繁清缓存绕过仍生效的 429 等待。源 teardown 清理对应版本健康记录；完整更新/回退联动仍由 OR6 接续。

## 复核与修正

独立只读 reviewer 复现 3 项 P2，均已先留 RED 后修正并复核关闭：

1. 429 内部等待期间其他查询绕过限制。补即时观察；又重放“两请求先准入，后来收到更长等待”的场景，补每次尝试前的最新等待/许可校验。原复现 270ms 时 `a=2,b=1`；修正后 `a=1,b=1` 且仍保持较长等待。
2. 空 URL 被当成结构变化，三档缺失导致可用的 128k 被冷却。现在按档位不可用处理，回归证明前三档空时仍可取得 128k。
3. 仅凭墙钟检查 URL，真实 6 分钟而墙钟只走 1 分钟时仍命中。缓存增加单调期限；另覆盖普通健康成功不能错误阻断其他有效并发请求。

整套回归还发现取消时序与安全错误文案兼容问题，已保持实际源请求/取消通知及 HTTP 429 可见状态。两次热词旧测试失败的日志显示：测试持续 `readFile` 轮询与 Windows 原子替换相撞，产生 EPERM rename；现暴露实例 `flush()`，先等该 writer 再进行同一磁盘断言，退出也等待热词写入。没有放宽持久化断言或只扩大轮询超时。

## RR 与边界

RR04/RR10：能力隔离、缓存不证明恢复、资源/档位不计故障有受控证据。RR05/RR11：429 共享等待、后到更长等待、单探测、取消释放与手动限频已覆盖。RR09：期限、回拨、普通拒绝/解码、已确认令牌过期、目标档不被降档缓存跳过已有生产回归。RR19：沿用并重跑队列重排、切歌取消、绑定与实际播放后收集回归。RR20：关闭新增策略、缓存清理与保存资料边界已覆盖。

本期没有声称每一条历史网络辅助路径都已接入健康层；艺人图片、独立下载内部抓取、质量徽标补全等仍沿用原边界。真实源错误只提供未知文本时保持 unknown，不能假称已准确分类所有连接故障。源更新/回退事件、跨桶总容量协调、完整真实探针和人工听感仍属后续阶段。没有运行旧复制实际 profile 的 E2E 或 diagnose，没有提交、推送、安装或发布。
