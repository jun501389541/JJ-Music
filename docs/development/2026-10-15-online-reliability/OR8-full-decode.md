# OR8 两平台固定样本的完整内存解码

日期：2026-10-16。沿用用户此前对指定目录全部音源及自选样本的授权，按[完整解码计划](../../superpowers/plans/2026-10-16-online-reliability-full-decode.md)执行。这是[短时解码](OR8-short-decode.md)之后的新观察，不改写此前失败和短播结果。

## 范围与方法

仅使用已通过既有静态准入的 HYWmusic_公益版_v1.0.3.js，执行前再次核对 SHA-256 为 0fdb240b65bdd63bac717c9c4fa9dd4099a24c24b593a3447993d048208b28a0。复用既有网易云、QQ 固定样本，不重新搜索、不换源或换曲重试；两条样本的目录时长均为 04:16。

生产测试模块重新由 tools/build-test.mjs 构建。每平台建立独立 source store，通过生产 SourceEngine auto 和 Windows 受限宿主初始化及解析 128k 档位，再经生产 safeFetchResponse 的公开地址、重定向和 DNS 固定守卫，将媒体流送入 FFmpeg 9.0.2。FFmpeg 使用 -xerror、-err_detect explode，选择首个音轨解码到 null sink，没有 -t 提前截断参数，不写音频文件。

每平台仅一次尝试：初始化和解析合计最多 60 秒；媒体传输和解码共用 120 秒、32 MiB 上限。通过必须同时满足：响应完整而非部分 Range，自然读取 EOF，已知 Content-Length 与实际字节数相同，FFmpeg 退出 0 且无错误级诊断，progress=end，解码时长与目录时长相差不超过两秒。只有解码器退出 0 或流提前结束不足以通过。

原 HYW 脚本执行前后哈希一致；同时逐份复核原清单 21 份脚本，changedSourceCount=0。源宿主正常 stopAll，reader 和 FFmpeg 均关闭，两个专用临时 source store 已按路径边界检查后回收。没有读取或改写日常播放器资料，没有音频落盘。

本地可复核产物位于忽略版本控制的 .cache/online-reliability-or8-decode/：decode-full-samples.mjs 与 full-decode-report.json。报告带本次 runId、状态、固定时限与流量上限、平台、目录/解码时长、HTTP 状态、字节和清理证据；不含媒体 URL、响应头原文、原始源错误或音频内容。

## 验证边界

本次证明一个指定源的两个固定样本响应完整传输，且 FFmpeg 可严格解码至自然结尾，时长与目录样本一致。它不证明录音身份、实际平台归属、真实码率/无损档位、主观听感或产品 UI 日常播放；报告里的 128k 是请求和源返回的档位标识，未当作媒体码率鉴定。其余源的全曲解码也未由这两项结果覆盖。

OR8 的作者日常操作确认、人工听感、真实源更新回退及安装升级继续保留待验收。本轮没有修改生产代码，没有新增完整 verify 运行、提交、推送、安装或发布。
