# 本地缺失文件逐首重新定位开发记录

日期：2026-10-23。用户已确认功能、逐首手动选择范围和设计，并授权实施。开发分支 `codex/local-file-relink`，基线为本地 main `95c53b1`。实现与验收完成后，用户另行明确选择提交并合并到本地 main，不推送、不发布。保留既有 `.graphflow` 本地资料。

## 实现

本地歌曲右键“文件 → 重新定位文件”，主进程验证旧记录后打开单文件选择框，展示旧、新标题/歌手/时长与路径。用户确认后修复曲库、收藏/歌单、最近播放、LastSession、当前和历史队列中的对应本地引用。取消保持记录；原文件可访问、候选变化/过期或目标冲突时拒绝。不自动播放，不修改音乐原件。

沿用路径生成 ID；仅同时匹配旧 ID 和旧本地路径的条目迁移，在线同 ID 不变。新文件标签和资产来源重新读取，不复制旧侧车来源。待写入资料保留原资源，需在既有页面重新选择目标；旧下载历史不重定向。

先写逻辑事务 `local-relink.pending.json`，再读取当时磁盘内容并逐份修复，不回放旧完整快照。每步幂等；启动先恢复再加载服务。损坏 JSON 或引用结构在创建事务前拒绝并保留原件。

确认阶段阻止新资料 IPC，并等待既有 IPC/资产写入落定。扫描或下载仍活动时拒绝并请稍后操作，退出等待在途事务。提交后重载失败，即使事务日志已删除仍保持写入锁，须重启读取已提交资料。播放器实际状态入口阻止维护期间来自任务栏、桌面歌词和媒体按键等播放/队列操作。

## 裁定

- Ruling：目标冲突检查包括未索引但仍在歌单/播放记录中的本地引用，避免重复 ID；首版不自动合并此类目标。
- Ruling：扫描/下载活动时拒绝并允许稍后重新选择，不后台终止用户任务。
- Ruling：由用户预览确认录音身份；候选读取前后及提交前复核 size/mtime/device/inode，不承诺识别保持这些属性不变的外部恶意替换。
- Ruling：提交前排空设置队列，维护期间暂停会话写入；保存位置绑定原本地身份。缺失媒体报零时读取匹配的 LastSession，避免覆盖恢复点。
