# 当前曲多个命名时间点书签设计

日期：2026-10-27。状态：用户已整体批准，已实现并通过自动验证及独立最终审查；未提交发布。见[开发记录](../../development/2026-10-27-track-bookmarks.md)。

## 用户已选范围

后续功能按逐首进度记忆→歌曲时间点书签→播放统计日期筛选与趋势顺序开发。第一项已完成验证，本项用户选择“当前曲管理多个命名书签”，点击只seek当前曲，暂停保持暂停。不做独立跨歌曲书签总览，不定义跨队列点歌。

沿用codex/manual-crossfade隔离工作树。排序/撤销/歌词偏移/统计/逐首进度等前置未提交源码全部保留；本批不提交、推送、合并或发布。人工听感继续独立待验。

## 交互方案

共用播放菜单增加“本曲书签…”入口，底栏和全屏播放一致。打开当前曲专用管理对话框，标题显示曲名、平台，内部列出本曲时间点和名称；沿用应用弹层样式，不新增路由或全局列表。采用对话框而非50个多级菜单项，方便滚动、命名与确认删除。

可在播放或暂停时打开；列表按positionMs升序、id作稳定平局键。添加、重命名在此对话框内编辑名称，避免多层prompt争抢现有单dialog状态。删除先在行内明确确认，再调用保存；取消不写。第一版仅逐个删除，不做清空/批量操作/导入导出/云同步。

点击“添加当前位置”时捕获实际当前曲媒体时钟，而非打开窗口时的旧进度；随后填写名称期间曲目可继续播放，保存仍使用捕获点，不能随时间漂移。显示捕获时间与曲名平台；预填“书签 MM:SS.S”，允许修改，trim后1–80个UTF-16字符，拒绝空白或超长。名称可相同，时间位置不能重复。

实现使用独立书签上下文校验，不复用依赖已有续播捕获点的trackResumeContext；没有任何续播记录的歌曲仍可添加书签。当前位置直接读引擎，不误用界面可能滞后的currentTime或旧续播点。

位置以100ms精度向下取整（floor(timeSeconds*10)*100），0允许，必须小于实际有限正曲长毫秒；未知/无限时长、加载中、实际媒体未匹配当前身份时禁用添加/跳转，但已有记录可查看。每曲最多50条、总计50000条/50000曲上限；满额时禁用新增并说明原因，不淘汰旧记录。相同完整身份同一100ms位置已有书签时拒绝新增并提示已有名称，不静默覆盖或自动改名。

每行提供“跳转”“改名”“删除”。跳转不重load、不替换队列，保持当前播放/暂停；先退出A–B，沿用现有seek收束渐变或取消未发声预载，睡眠/音量/歌词校准/撤销不变；统计排除跳过部分，逐首进度记录按既有采样更新，书签不会消费“从上次继续”捕获点。改名不改变时间或ID；修改时间留待后续范围，不在此版实现。

新版本媒体时长变短导致书签越界时仍展示，标记“超出当前时长”，禁跳转；允许改名/删除，不静默夹到曲尾，不自动删除。没有任何书签、加载记录和读取失败分开呈现。错误只影响书签，音乐仍可播放。

## 当前曲与过期窗口保护

打开对话框捕获完整playlistEntryKey、playGeneration及本次加载访问ID，展示固定的原曲标题。切歌/同曲重播/维护开始导致窗口过期：显示“歌曲已变化，请重新打开”，禁用所有写入和跳转；不能自动切换到新曲书签。自动URL重试导致播放代次变化，也使旧窗口过期；不依赖裸ID比较。

新增捕获点绑定窗口与曲目身份，提交前再次校验当前窗口仍有效、实际加载身份匹配、捕获位置仍在当前合法曲长内；音频继续推进不使捕获点过期。暂停不使窗口过期。

修改/删除捕获书签id和原名称、位置作为期望值；主进程串行事务比对目标是否仍存在且与预期一致，过期拒绝。所有写操作对当前窗口有busy保护，禁止双击新增/重命名/删除并行；保存期间禁用本窗口其它写入口，取消编辑不能撤销已接受的请求。

确认提交进入IPC后再切歌，已接受事务仍只写原完整键，不能转写新曲或回滚成另一个对象。结果按单调revision合并；过期窗口不跳转、不恢复到新曲、不声称保存的是新曲。新打开窗口读取已确认记录。跳转执行前也按窗口和原书签快照重新校验，已删除/改名的旧行拒绝。

## 原子存储

独立track-bookmarks.json，version1、revision非负安全整数；records为完整歌曲键到Bookmark[]映射，Bookmark={id,positionMs,name,createdAt}，id由主进程生成UUID。文件不存音频路径/URL/封面/歌词、播放快照或访问ID。相同完整身份的重复队列行共享，跨平台/本地相同raw ID隔离；本地重新定位如完整键未变则沿用，键变化不自动迁移。

全文件<=8MiB、全局<=50000条且<=50000个非空键，每曲<=50。键沿用现有前缀和4096长度上限；positionMs非负安全整数且为100倍数；name为规范trim后1–80字符；createdAt非负安全整数；id有效UUID、全局唯一，同曲positionMs唯一。空数组不落盘，删除最后一条移除该键。读旧书签不因当前媒体曲长变化判坏；只有跳转/新建按实际曲长判定。

主进程提供get/add/rename/remove受控IPC：参数严格白名单复制、主窗口来源校验、单次操作、不允许任意文件路径和任意整文件替换。add验证key/position/name并检查当前位置重复/容量后生成UUID；rename/remove对完整原值做比较交换。文件候选整体校验和字节限制，串行原子写入成功才更新records/revision并应答；失败保留旧文件和内存，不自动重放非幂等新增。UI可手动重试，不能在失败时假显示新书签。

缺文件正常为空；坏JSON/未知版本/非法条目/重复ID或位置/容量超限整体不可用，不静默跳过或覆盖为空。renderer初始化完成前禁止操作；坏文件时展示错误、禁用书签写入，但播放器其它功能继续。关闭和数据迁移拒绝新写、flush已接受事务，迁移复制该独立文件；不扩展现有歌单JSON备份。

## 自动验收

| 场景 | 预期 |
| --- | --- |
| 播放中捕获时间后命名，暂停添加 | 保存最初捕获的100ms点，不随输入时长漂移；暂停不启动 |
| 同曲多点、相同名称、同100ms位置、0、曲尾、未知时长 | 时间排序稳定，同名允许、同位置拒绝；严格边界 |
| 点击书签，暂停/播放/交叉渐变/AB | 真实seek，状态保持；AB退出、渐变沿现规则，歌词和统计协调 |
| 切歌、同曲重载、自动URL重试、维护、旧行被改名/删除 | 旧窗口与跳转拒绝，原数据和新曲播放不被改写 |
| 请求已接受后切歌、双提交 | 只提交原完整键一次，忙保护，单调响应不覆盖新数据 |
| 每曲50/全局50000/8MiB、原子写失败、并发 | 整次拒绝不淘汰，旧内存/磁盘保留，不丢其它曲修改 |
| 正常重启、损坏/未知版本/重复ID或位置 | 恢复原点；坏文件保留并禁写，音乐仍可播放 |
| 本地/平台同raw ID、队列重复行 | 完整身份隔离；同键共享，不改源歌单或队列 |
