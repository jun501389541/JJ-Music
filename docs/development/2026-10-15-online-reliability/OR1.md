# OR1 — 结构化错误、预算与脱敏诊断

实施状态：首期资料路径已接入。规则：OR-03、OR-04、OR-08、OR-11、OR-12。

## 实现

- `src/shared/online-reliability.ts` 定义可 IPC 传输的错误、上下文和缓存状态；原始 Error、AbortSignal 不传 IPC。
- `reliability-policy.ts` 保守分类，固定安全文案；无证据时 unknown。JSON 解析异常为结构错误，明确网络错误可重试一次，默认 12 秒总预算 / 6 秒单次 / 250–750ms 退避，支持唯一重试所有者。源引擎与播放器没有再包一轮重试。
- 搜索 HTTP 边界保留状态，429 传递 Retry-After；等待超预算立即结束。普通 403/404 保持 unknown，不猜歌曲下架或 URL 过期。
- `online-diagnostics.ts` 仅白名单事件，本地最多 500 条 / 2 MiB；记录与导出各做一次白名单重建，不导出 message、搜索词、歌名、路径、歌词、URL、请求头或任意版本字符串。仅受控 ID/修订/摘要可进入事件。
- 本期资料事件有平台、能力、阶段、版本、尝试/缓存状态；数据目录下持久化，读损坏日志不阻止启动，写失败保留内存。
- 设置 → App 数据支持持久化诊断开关、清除日志、通过用户选择的保存位置导出白名单 JSON。没有遥测或上传。

## 验证

基础模块不存在时，编译后的新增测试失败；实现后分类、唯一重试、超预算 429、取消、忽略 signal 的挂起适配器、500 条上限和敏感字段排除通过。实际 HTTP 429 曾在独立复核中丢失证据，已用生产 searchOnline 的合成 Response 重现 RED，再修正为 GREEN。

样本均为测试内构造的 Error/Response/规范化对象。真实听感没有验证。最终结果见 OR2 的验收表。
