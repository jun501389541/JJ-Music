## 实际代码依据

- `src/renderer/src/stores/player.ts`：ResolvedSource 只保存地址、成功档位和音源名字等，尚未完整分离原歌曲与替代资源身份；sameRecording 仅严格匹配名称/歌手字符串和五秒时长差。
- resolve 先请求原平台的默认可降级路径，失败才换平台，尚不符合“所有平台同一目标档尝试完再降低一档”。
- URL 缓存按原平台/歌曲/绑定音源/目标档位建立，TTL 为五分钟，需要识别成功档位及源版本和可用性变化。
- `src/main/sources/source-engine.ts`：已有 strict 参数和音源版本返回信息，可复用；默认 false，底层仍可能按音源各自降档。不能只修改渲染层顺序而保留内部降档。

## 开发顺序

继续 D-B → B1 → B2 → B3 → B4 → G-B。D-B 先提出具体音源顺序、匹配边界、预算、缓存及检测方案；产品规划要求会影响听歌结果的取舍由用户确认。原有音质优先与不确定候选不自动播放原则已确定，不重新征求这些已获授权的规则。
