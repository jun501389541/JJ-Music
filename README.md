# JJ Music

**面向 Windows 的桌面音乐播放器，支持本地曲库、在线音乐、歌词、音质选择下载和跨平台歌单导入。**

当前版本：**0.1.7** · Windows x64 · Electron / Vue 3 / TypeScript

## 下载

前往 [Releases](https://github.com/jun501389541/JJ-Music/releases) 获取发行版本：

- [Windows 安装版](https://github.com/jun501389541/JJ-Music/releases/download/v0.1.7/JJ-Music-0.1.7-Setup-x64.exe)：按向导安装。
- [Windows 免安装版 ZIP](https://github.com/jun501389541/JJ-Music/releases/download/v0.1.7/JJ-Music-0.1.7-Portable-x64.zip)：完整解压后运行 JJ Music.exe，保留全部文件。
- [SHA-256 校验文件](https://github.com/jun501389541/JJ-Music/releases/download/v0.1.7/SHA256SUMS.txt)。

运行发行版无需安装 Node.js。更新前请先退出旧版；安装版和免安装版默认共用当前用户的配置。

0.1.1 至 0.1.5 的 Windows 包在部分电脑上无法启动音源（在线播放随之失效），请使用 0.1.6 及以后版本。

## 功能

| 功能 | 说明 |
| --- | --- |
| 本地曲库 | 文件夹扫描、增量索引、歌曲 / 曲风 / 专辑 / 艺术家分类与数量 |
| 发现音乐 | 最近播放、曲库概览 |
| 全局搜索 | 本地结果支持拼音全拼与首字母，输入时有联想提示（顶栏的放大镜与搜索页同一套）；未输入时显示搜索历史与热门搜索词，两者可在设置里各开关；在线可搜 QQ、网易云、酷狗、酷我、咪咕；本地命中只在第一页置顶，计数行按曲库如实报告 |
| 浏览位置记忆 | 侧栏每个栏目记住你上次看到的页面：换回来时滚动位置、下钻的专辑/艺术家、搜索关键词都在原处，点「专辑」会回到刚才在读的那张而不是网格顶部（标题栏 返回 仍是 详情 → 网格 一步）。会话内有效，不写进设置 |
| 播放界面 | 封面、歌词、频谱、播放列表、EQ、播放速度、睡眠定时；整页背景是当前封面的虚化色彩（设置 → 播放界面 的「霞光特效」），封面下方带自身倒影；频谱是从进度条往上长的淡色剪影，垫在歌词与封面后面 |
| 桌面歌词 | 应用之外的置顶悬浮窗显示当前歌词行，可拖动、锁定穿透、四档字号 |
| 系统媒体控件 | Windows 的锁屏界面、音量飞出菜单与键盘播放键能显示当前曲目与封面，并直接 播放/暂停、上一首、下一首（走系统媒体会话，不需要常驻后台进程）；任务栏图标悬停时另有三个按钮 |
| 音源管理 | 导入 LX Music 自定义音源协议兼容脚本（可粘贴 .js 或直接从网址拉取）；自动抽测平台状态 |
| 在线下载 | 选择音源支持的音质、批量下载、进度、取消、失败重试、断点续传、同名文件保护 |
| 歌词与标签 | LRC 保存，MP3 / FLAC 嵌入歌词及封面，包含平台提供的翻译和罗马音；在线歌词可切换来源（音源脚本 / 平台接口 / 联网匹配其他平台）；写入位置可选（文件标签 / 同名文件 / 两者），联网取得的歌词先进「待写入」，确认后才落盘 |
| 歌单导入 | 网易云、QQ、酷狗、酷我、咪咕公开网页版歌单链接或 ID；同步导入平台封面，保存前可拖动排序与移除 |
| 艺术家 | 曲库按标签归并；头像可从平台联网获取，取不到时退回该歌手的专辑封面 |
| 个性化 | 深浅主题、强调色、歌词外观、列表密度、快捷键与多级菜单 |

## 开始使用

1. 在“音乐库”添加音乐文件夹，扫描本地歌曲。
2. 在“音源管理”导入可信的 .js 脚本或兼容的 user_api.json，启用后查看平台验证状态。
3. 在“全局搜索”查找歌曲。在线歌曲右键 → 下载歌曲 → 选择音质。
4. 在“设置 → 下载”选择目录，设置 LRC、嵌入歌词、翻译、罗马音和封面；在“设置 → 标签与文件”选择写入位置（音频文件标签 / 同名文件 / 两者）与允许改写的格式，并处理「待写入」列表。
5. 在“导入歌单”选择平台，粘贴公开歌单链接或 ID，读取后可以拖动排序、勾选移除不想要的歌曲，再保存为新歌单（封面一并导入）。

平台“抽测通过”只代表本次样本可用，不保证所有歌曲都能播放或下载。项目不随包分发第三方音源脚本或音乐文件；第三方脚本具有当前用户的文件和网络访问能力，请使用可信来源。

## 从源码运行

使用 Node.js 24、npm 和 Windows x64。

    git clone https://github.com/jun501389541/JJ-Music.git
    cd JJ-Music
    npm ci
    npm run dev

开发与验证命令：

    npm run verify      # 类型检查、生产构建、离线测试
    npm run test:e2e    # 真实 Electron 播放验证，需要可用本地曲库
    npm run pack        # release/win-unpacked 完整免安装目录
    npm run dist        # Setup EXE + Portable ZIP

打包输出：

    release/
      JJ-Music-0.1.7-Setup-x64.exe
      JJ-Music-0.1.7-Portable-x64.zip
      SHA256SUMS.txt          # 由 npm run dist 生成，只列本次版本的两个文件
      win-unpacked/

npm 缓存放在 `.cache`。Electron 与打包工具的二进制镜像改为通过环境变量配置（`ELECTRON_MIRROR`、`ELECTRON_BUILDER_BINARIES_MIRROR`），不再写入 `.npmrc`，因此默认从 GitHub Releases 获取；下载不通时按上面的变量指定镜像即可。打包脚本会先重新构建源码，并清除测试环境开关。

## 数据与限制

- **数据目录**：便携版（ZIP）与"程序目录可写"的安装版，把全部数据放在 exe 旁边的 `data/`；程序目录不可写（如装进 `Program Files`）时回退到 `%APPDATA%/jj-music`。Chromium 的缓存随数据目录一起走，不会单独留在 C 盘。首次以便携版启动时会把旧的 `%APPDATA%/jj-music` 复制过来（原目录保留，浏览器缓存等可再生数据不复制）。设置 → App 数据 显示当前目录与来源，并提供「迁移到其它目录」：选完目录后复制并写入 `data-location.json` 指针，需重启生效。目标目录不能与当前数据目录互相包含——选它里面的文件夹会让递归复制一层层套进自己，选上级则会把应用文件散开，这两种在弹确认框之前就会被拒绝。迁移过的便携版如果那块盘当天没插，会回到程序旁边的 `data/` 并在设置页说明，不会改到 C 盘去建新库；记录里的目录"在但写不进去"（同名普通文件、只读挂载）同样不会被采用，并且会说清。命令行显式传 `--user-data-dir` 时以它为准（测试与自动化入口依赖这一点）。
- 支持 Chromium 可解码的 MP3、FLAC、M4A、AAC、OGG、Opus、WAV；APE、DSD、WMA 暂不支持播放。
- **可以安全删掉的东西**：`data/`（或 `%APPDATA%/jj-music`）里的 `Cache`、`Code Cache`、`GPUCache`、`blob_storage`、`DIPS` 等是 Chromium 自己的缓存；`library/covers`（抽出来的封面）与 `library/flac-repair`（无损播放时的修复副本）是派生文件。删了都不会丢数据：应用启动时会发现封面引用失效，自己重新抽取，不需要手动点「重新扫描」。真正不能删的是 `settings.json`、`playlists.json`、`downloads.json`、`library/index.json` 与 `sources/`。
- **封面与歌词的来源会被记录**：每首曲目的封面和歌词在索引里存成一条有序来源链（文件内嵌 / 同目录 `.lrc` / 应用缓存 / 平台接口 / 用户手工），播放页徽标与右键「音轨信息」都会写出现在用的是哪一处。解析优先级是"用户放的 > 文件自带的 > 联网抓的"；这张表只影响读取与显示，写标签仍然只在你点「写入标签」时发生。索引版本随之从 3 升到 4，首次启动会自动在后台重读曲库补齐，无需手动重扫。
- **写入位置与「待写入」**：设置 → 标签与文件 决定「写入封面与歌词」落在音频文件标签、同名文件，还是两者都写；格式不能改写时自动退到同名文件并说明原因。播放一首本地歌时联网找到的歌词**不会**自动改你的文件：它先进待写入队列（`library/pending-assets.json`，重启还在），徽标写「（待写入）」，你在这页或歌曲菜单里点「写入」才落盘，也可以整个丢弃。丢弃是按歌、按那条词本身记的：同一条不会在下次播放时再回来烦你，换了一条不同的还是会提示（第一次很可能匹配错了歌）。可以改写哪些格式也在这页勾选，这个开关只能收窄、不能放宽应用真会写的格式集合。索引版本因此从 4 升到 5（封面同名文件是新读出来的字段）。
- **同名文件与封面**：歌词认 `<与音频同名>.lrc`（唯一的命名约定，模糊后缀各家规则不一致，这里不猜）；封面按 `<与音频同名>.jpg/.jpeg/.png/.webp` 找，再认目录级的 `cover` / `folder` / `front` / `albumcover` / `album`。写封面时只用与音频同名的那一个名字，不去动目录级的 `cover.jpg`——那可能是用户为整张专辑放的。MP3 的歌词写进 `USLT`、FLAC 同时写 `LYRICS` 与 `UNSYNCEDLYRICS`（部分播放器只认后者）；不写 ID3 的 `SYLT` 帧，因为现用的写标签库对这类帧只追加不替换，重复写会留下互相遮蔽的旧词。
- 标签嵌入支持 MP3 / FLAC；其他下载格式保留音频并提示限制。
- 内置在线歌词查询覆盖 QQ、网易云、酷我、咪咕；翻译与罗马音取决于平台返回内容。在线歌词可在“设置 → 歌词”里选首选来源（音源脚本 / 平台接口 / 联网匹配其他平台），并可关闭“其他来源兜底”；播放页的歌词菜单能对当前这首临时换一种。
- 下载支持断点续传：中断后 `.part` 保留（包括"请求阶段就失败"的断网、403、取消），重试带 `Range` 从已写字节继续。只有服务器答 206、`content-range` 的起点确实等于我们请求的偏移时才当作续传接上；服务器忽略 `Range` 返回整份时会重头下载而不是拼接。文件有没有被换过由 `If-Range`（首次的 `ETag`/`Last-Modified`）判断，服务器两个都不给时改用整份长度是否变化判断；都对不上就丢弃那段并已"整份重下"的方式重来，绝不再拼出能播放却混了两版音频的文件。同时运行两个任务，每批最多 500 首，单文件最大 1 GB。
- 歌单导入保存本地快照，不自动同步。每次最多读取 5000 首，私密歌单、短链接或平台访问限制可能导致无法完整读取。导入的封面来自平台，抓不到时只提示、不影响歌曲导入。
- 热门搜索词接了四家：QQ、网易云（热搜榜 `HOT_SEARCH_SONG`）、酷我（`hotword.kuwo.cn`）、酷狗（`gateway.kugou.com` 的「热搜榜」，它一次返回九个榜各 30 条，只取第一个）。后两家的端点取自 lx-music-desktop：本机实测之前试过 `mobile.kuwo.cn` 返回 `Hit=0`、酷狗的搜索主机连不上，那是**端点选错了**，不是这两家没有热搜。咪咕没有公开端点，那一家的页签里这一栏整行不出现，不会转圈占位。单家约 20 条，「全部」把四家轮流并起来、上限 48 条。QQ 的主机偶发连接失败（实测同一 URL 一次 500、下一次 30 条），失败冷却只有 15 秒，切页签会再问一次。
- 网络抓来的内容都按"抓一次、留着用"来记，不会因为反复进出页面而反复问平台。**热门搜索词**每家平台每个自然日只问一次，结果写在 `library/hot-words.json` 里，所以重启应用也算"今天已经问过了"；跨过零点的那一次先把昨天的词立刻显示出来、同时在后台换成今天的，用户不等网络。**艺术家头像**按歌手名记在 `artist-images.json`（有没有都记），扫描到新名字时在后台按最多两个并发补查（每轮最多 120 个名字），之后只有你点「更新网络头像」才会再问；从曲库移除歌曲不删这份记录，所以重新导入的专辑首帧就有头像。取不到新数据时一律保留旧数据：失败只记一次退避（半小时），不会把今天写成"这家没有热搜"。
- 艺术家头像来自各平台的公开接口，只按标签里的歌手名搜索匹配：名字近似但并非同一人时有可能取错，取不到则沿用专辑封面。酷我的艺人接口需要签名，不参与。"没查到"要四家平台里至少有一家真的答了话才算结论，网络不通造成的查不到不会被记成"这位歌手没有头像"，下次进这页会再问一次。
- 在线能力依赖外部平台和用户提供的音源，接口变化可能影响可用性。
