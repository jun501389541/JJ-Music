# 播放数据备份恢复与书签总览

用户选定两项按顺序开发，并明确“按建议直接开发”，授权自行确定细节，沿用Electron/Vue与当前隔离工作树，不重复设计确认，不提交推送。

## 第一项：播放数据备份恢复

设置/数据增加独立JSON导出、选择文件预览、确认补缺。四类别为歌词偏移、逐首续播、当前曲书签、播放统计（含基线和每日明细）。备份kind=jj-music-playback-data、version=1、createdAt ISO，数据全量白名单校验，总文件最大64MiB，各类别仍受原容量限制。不含音频、歌词正文、URL、脚本和认证资料，身份可能包含本地ID，统计有曲名歌手。

按歌曲完整身份和类别补缺：偏移已有key不替换，续播已有key不替换，书签已有整曲组不替换，统计已有key及其日期不替换，不相加。预览显示每类已有/新增身份数量，不写文件；提交时重新判断缺失，避免预览期间新记录被覆盖。统计保留导入曲目全部baseline/daily；本机coverage起点不向前扩展以免把缺失历史伪造为0。

备选整份覆盖会丢失本机新增记录；逐字段合并会令书签与统计重放不清晰，因此采用用户认可的补缺。四个现有独立原子文件不承诺跨文件事务：依序执行，单类别失败时停止，返回已完成类别/错误；重复选择原备份只补剩余类别。即使最终响应丢失，重试不重复累计。容量或损坏在各类别完整校验前不写该类别。导出失败不覆盖目标，禁止写入资料目录（含已有软链接目标）。

主进程原生选择，renderer不传路径或数据。单预览10分钟令牌，选择新文件使旧令牌失效，确认前消费，导出/恢复互斥；关闭和迁移禁入。恢复刷新四客户端权威快照，不切歌、不替换队列，尚未确认的renderer尾段不包含于备份。

## 第二项：书签总览与跨歌曲跳转

侧栏独立只读总览，可按书签名、曲名、歌手、身份搜索，分页100行；显示时间点、平台和无法匹配状态。使用完整身份索引，优先当前本地库资料，其次当前队列/最近播放/歌单；只使用已保存曲目资料，不根据任意备份字符串构造媒体路径。恢复书签未匹配时保留且禁播，重新匹配可刷新。

同当前已加载曲跳转复用现有书签context与校验，暂停仍暂停。其他曲以独立单曲队列播放并从书签位置开始，明确按钮“播放此处（切换队列）”；沿用正常播放解析、维护锁、播放代次、错误处理，不使用异步播放后裸seek，防止用户途中切歌串曲。既有队列历史记录规则保留，不添加跨曲自动播放列表。

独立审查后的实现取舍：先暂停载入，等待实际媒体时长，在同一同步段确认请求所属尝试代次、用户toggle与seek代次、书签原值及位置边界后定位并播放。内部重试只更新本请求所属代次，不采纳期间的用户操作。此方案替代挂在loadedmetadata上的旧startAt回调，用户新seek不会被旧回调覆盖；实际时长越界保持暂停并显示错误。新选曲与维护操作使旧请求失效。该调整经原生RED→GREEN回归验证。

## 验收

生产bundle测试：四类往返/冲突/统计不相加/重复恢复/损坏/超限/逐类别失败/并发排队/令牌过期；身份解析不同平台不混淆、缺失禁播、起播点和暂停跳转保护。完整verify，生产Electron DOM与生成媒体探针；独立审查。真实源、升级、人工听感独立待验。
