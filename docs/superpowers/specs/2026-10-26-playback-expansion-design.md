## 实施方式

建议同批交付、分三步验证：片段循环 → 睡眠停止规则 → 跨队列渐变。三项共同影响 progress、ended 和预约取消，依次落实共享边界更便于验证。

用户已确认三项全部开发，并选择睡眠到点退出 A–B、播完整首后停止。其余细则为实现方提议，随完整设计交用户批准。

三项共同影响同一播放器状态；并行修改增加状态冲突，互不协作的独立实现又不能满足睡眠退出循环。建议按上述依赖顺序实现并共同验收，沿用 Vue/Pinia 和现有双通道，不引入新依赖。

## A–B 片段循环

- 为正在播放的单首歌曲设置 A 点和 B 点；要求有限已知时长、可定位，`0 <= A < B <= duration`，建议片段最少 1 秒。
- 使用当前进度设置端点，显示两个端点及循环状态，提供清除操作；未设置有效 B 前不开始循环。
- 到 B 后定位 A；暂停不清除端点，恢复后继续。普通循环回跳不生成新播放历史，不改变原队列或随机播放历史。
- 有效片段循环期间取消自动下一首预载，禁止片段边界触发跨曲交接；用户主动选其他歌曲仍可切歌，成功后清除旧曲端点。
- 端点按完整歌曲身份绑定，只保留本次会话。切换歌曲后清除；跨队列请求准备失败仍留旧曲时保留端点。停止、退出后不恢复循环。
- 在片段外手动定位时，建议保留端点并暂停片段循环，用户可显式重新启用；不把用户拖动强制拉回 A。
- 初版使用现有进度事件和 seek 能力，不承诺采样级边界。需在原生媒体验收中记录实际边界偏差，不能以理想定时器断言替代实际证据。

## 睡眠定时

- 保留原有到点立即停止模式，新增到点后播完当前曲再停止模式；显示倒计时与到点后的等待状态，并能取消。
- 到点时以已实际开始播放的歌曲为准，等待其自然结束后停止；不自动进入下一首，不因单曲循环再次重播。
- 等待本曲结束期间取消自动预载，完成已开始的交接到已提交新曲；暂停时保持等待，恢复后继续等自然结束。
- 到点没有已加载当前曲时立即停止并取消在途播放；仅暂停时保留等待，恢复后等结束。未知或非有限时长到点立即停止，并提示无法等待自然结束。
- 用户主动开始另一首或新队列时，建议取消已经到点的“等待本曲结束”状态；尚未到点的计时继续，停止和退出仍清理定时。
- 用户已确认：到点退出片段循环，从当时实际进度继续到整首自然结束，不从头重播。保留端点但停止循环；等待结束期间须先取消睡眠等待才能重新启用循环。
- 不执行系统关机、休眠等设备操作；定时任务不跨应用重启保存。

## 跨队列交叉渐变

- 扩展明确的用户播放入口，覆盖歌单、曲库及搜索结果开始播放；沿用手动渐变时长，默认仍关闭。更新设置帮助文字以说明新范围。
- 内部错误重试、自动恢复、启动会话恢复及历史队列恢复保持原流程。本轮新增范围为用户从歌单、曲库和搜索结果开始播放；搜索单曲试听提交后仍保留试听属性。
- 保留一个待提交队列及其起始曲目、标签、模式和试听属性；准备时不修改现行队列、历史、随机顺序、歌词或媒体会话。
- 目标首次有效播放时一次性提交新队列与当前曲目，并记录旧队列历史；发声前失败完整保留旧状态。
- 渐变完成前目标失败且旧通道仍有效时，回滚旧队列、原模式、历史和旧曲实时进度；已实际发声的新曲保留播放记录。
- 历史和会话持久化需要与事务提交/回滚保持一致。不能在准备时调用带持久化副作用的 `rememberQueue`，也不能让迟到的保存覆盖较新意图。
- 连续请求以最新完整意图为准；新请求接管已开始渐变时先完成现有交接，再从已提交曲目准备下一目标，最多两个通道。
- 暂停、定位、来源变更、停止、删除或修改队列与请求代次失效需同时清理待提交事务。准备取消留旧；交接后的定位保留新曲。
- 新队列选中了当前同一完整歌曲身份时，建议不叠播同一曲；提交队列后沿用原有重播语义。无有效目标、空列表和不支持渐变能力时遵循既有路径。

## 三项协作与优先级

- 优先级为停止/退出 → 睡眠到点立即停止 → 睡眠等待本曲结束 → 明确用户选歌 → A–B 回跳 → 自动下一首；停止使在途代次失效。
- 有效用户换歌意图取消已到点的睡眠等待；无效下标或空选择不取消。尚未到点的计时在换歌和准备失败后都继续，不能被旧的队列切换隐式停止路径清除。
- 睡眠到点进入等待时取消尚未发声的所有准备，保留实际旧曲；已发声的渐变立即完成到新曲，等新曲结束。同轮 playing 与到点按播放器事件处理顺序确定唯一当前身份，只停止一次。
- 等待结束时终止性媒体错误立即停止并清理等待，沿用错误通知；不能延长既有解析、启动、卡顿恢复预算或自动跳到其他歌曲。
- A–B 活跃时取消自动预载；显式手动准备期间暂停片段回跳，避免 seek 清掉备用通道。准备失败或取消且仍为原歌曲时恢复原循环；新曲发声时清除旧端点。
- 渐变中失败回滚时恢复旧曲端点和启用状态；期间睡眠已到点则不能重新启用旧循环，不能撤销停止或复活被释放通道。
- 渐变中设置 A–B 先完成当前交接，端点属于已提交新曲。B 接近曲尾时 progress 和 ended 共用循环边界判断，不能既回跳又推进队列。

## 跨队列事务边界

- 新增显式用户新队列动作，内部 `playQueue` 与 `playQueueSnapshot` 保持既有语义。核对歌单、曲库、搜索、榜单和公开歌单预览的直接播放入口，用户新队列播放统一走该动作；历史列表恢复仍排除。
- 快照包括旧队列、索引、标签、模式、试听属性、随机池与实际历史、队列历史、旧曲播放/歌词/解析状态和 A–B 状态。目标队列复制并按完整身份校验，不跟随 UI 后续变动。
- 交接时使用旧曲实时进度；提交前不生成新队列历史，也不记录未发声目标。
- 发声后才提交历史；历史和会话保存顺序化且受版本保护，回滚后的最终保存不能被较早写入覆盖。只保存所拥有字段，不回滚同期无关设置。
- 保存失败单独提示，不因磁盘错误回滚已发声媒体；内存状态保持正确，不把失败写盘报告为已保存。
- 准备中队列编辑、换模式、来源变化或本地文件重新定位使快照失效时取消。已交接后编辑先完成交接，再按现有规则编辑，不用旧快照撤销较新编辑。
- 手动时长设为 0 时，准备中的相同新队列意图转原流程；已发声的交接立即完成。非零更改只影响后续请求。旧曲未播放、目标同身份或引擎无准备能力时沿用原流程。
- 当前队列和跨队列点选共享最新意图与未播放随机抽取归还。新队列准备中的上一首/下一首先取消待提交事务，再在实际旧队列导航。
- 旧曲先结束时睡眠等待优先停止；否则仍有效的新队列目标经有界原流程只推进一次，旧队列不能同时自动下一首。短曲/未知时长仍须先准备，再零时长交接，不停止旧曲后重复解析。

## 界面与状态契约

- A–B 的设置 A、设置 B、启用/暂停循环、清除入口复用播放更多菜单；现有播放状态区展示端点。无效端点禁用或明确提示，不静默调换 A/B。
- 睡眠菜单保留 15/30/45/60/90 分钟及取消，新增到点处理方式；切换方式不重置既有倒计时。状态显示剩余分钟或“播完当前曲后停止”，不高频写盘。
- 跨队列准备在原状态区展示目标与来源列表，不提前改旧歌名、封面。失败只通知一次，不污染旧曲错误链。
- 睡眠等待、准备切换、A–B 与歌词按优先级组合展示，各功能取消入口始终可达。复用现有控件，不新增页面。
