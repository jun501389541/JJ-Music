# 普通歌单批量改名设计

日期：2026-10-25。状态：用户已批准设计并授权实施。

## 目标与范围

在“歌单 → 批量管理”中，为用户选中的普通歌单提供批量改名，并在写入前预览。用户已选择首版支持添加前后缀和文字查找替换。

首版提供两个互斥模式：

1. **添加前后缀**：将前缀和/或后缀添加到每个原名称。两项均为空时拒绝生成预览。
2. **查找替换**：大小写敏感、逐字匹配所有出现位置，不使用正则表达式；查找内容不能为空。替换内容允许为空，用于删除匹配文字。替换字符串中的 `$&` 等字符按普通字面文本处理。

两种模式分别预览和确认；一次操作不串联执行前后缀与替换。转换保留输入文本原样，不做 trim 或 Unicode 规范化；最终名称全为空白时拒绝整批预览。每个名称以 JavaScript 字符串长度计最多4096，输入片段最多256字符，超过上限或出现 NUL 时拒绝整批，不截断、不跳过。计算输出时必须先有界计算长度：前后缀模式在拼接前检查总长；查找替换先计算匹配数及结果长度，超4096立即拒绝，不能先构造可能大幅膨胀的字符串再检查。重复名称保持重复，按歌单 ID 独立改名。

不包含自动编号、正则表达式、歌单复制/合并、内置默认列表或收藏改名，也不改歌单 ID、曲目、文件名、收藏关系、歌单顺序或当前播放队列。

## 现有基础与入口

- `src/renderer/src/views/PlaylistsView.vue` 已有普通歌单选择、名称筛选和最多1000项的批量管理；默认列表与收藏不可选。
- `src/main/store/settings-store.ts` 的 `PlaylistStore.mutate` 将改动串行化，并在原子保存失败时回滚。单项 `rename` 目前只设置名称字段。
- `src/renderer/src/components/PlaylistDerivePanel.vue` 和 `PreviewLease` 展示了请求取消、预览确认、token 丢弃和迟到响应保护，可复用交互约定；批量改名应使用独立候选和IPC通道，不能清除复制/合并或其他功能的候选。
- 当前代码没有批量改名实现或现成设计。

在批量管理工具区增加“复制与合并”和“批量改名”工具切换。工具切换在预览请求或提交期间禁用；用户可先取消预览请求，收到 `busy=false` 后再切换。请求已完成时，切换卸载旧面板并丢弃其预览租约；选中的歌单仍保留。离开批量管理、筛选或选择变化、切换工具、显式取消、路由离页都会使本轮名称预览失效。选中顺序使用当前筛选后列表中的显示顺序，而非勾选先后。

## 预览与界面行为

- 每行显示歌单名称 `旧名 → 新名`；同时展示选中数、将改名数和不变数。无变化行也展示，便于确认规则结果；若没有任何变化，禁用确认。
- 修改模式或任一输入字段、筛选、选中集合或选中顺序后立即失效预览。预览生成中可取消；迟到的响应不能覆盖新一轮输入。
- 最后一步由用户点击“确认批量改名”。提交期间禁用重复确认、选择、筛选及模式切换。
- 成功后退出批量管理、清空选择并刷新歌单；若保存成功但刷新失败，明确告知已保存且无需重复执行。失败时整批回滚并提示重新预览。
- 预览和结果不改变播放状态；不播放、下载、联网、扫描音乐文件或读取本地音源。

## 数据边界与接口信任

- 每次最多1000个不同普通歌单 ID；拒绝空选择、重复 ID、未知 ID、NUL、默认列表及收藏。
- 在 `PlaylistStore` 的变更队列内读取名称快照，先验证每个名称不超过4096字符且非空白，再有界复制；不扫描或返回曲目数据。
- 预览候选（来源 ID/原名称/新名称与必要开销）序列化不超过20 MiB。超过后整批拒绝并提示分批操作。
- 渲染进程只能提交模式、有序 ID、变换文本和请求 ID；不能提交目标名称、歌单对象、曲目、路径或其他元数据。主进程根据快照计算结果，严格 IPC 拒绝未知字段和额外参数。
- 共享契约提供模式、输入验证和预览结果类型；主进程新建批量改名服务负责预览租约、变换及应用；`PlaylistStore` 提供轻量名称快照和批量更新方法；preload 只暴露具名 preview/apply/discard 方法。

## 并发、租约与原子性

- 主进程每个批量改名服务最多保留一个有效候选，UUID token 有效10分钟。新预览替换旧候选；discard 只丢弃 token 匹配的候选，避免旧组件清除较新的预览。服务维护代次，已取消或已被新请求取代的预览不能登记候选。
- Apply 同步消费一次性 token 后进入 `PlaylistStore` 串行变更。在保存时验证每个来源 ID 仍存在、仍是普通歌单且当前名称与预览时原名称完全相同。名称发生变化或歌单被删除则整批拒绝，要求重新预览。
- 并发校验只针对来源 ID 与原名称；曲目、封面、来源平台和位置的并发变化不应导致误覆盖，因为应用只在当前歌单对象上设置 `name`，保留保存时的其他字段。相同原名称重复出现视为同名稳定状态。
- 一次 Store mutation 更新所有变化名称并执行一次原子持久化。持久化失败恢复整批名称，后续排队中的更新仍可继续。全为 no-op 时不允许 Apply。
- 复用当前应用退出、资料迁移及本地文件重新定位维护锁：维护期间拒绝预览/应用；应用退出、资料迁移开始和本地重新定位维护锁取得时都主动清理候选。不得让旧候选跨维护边界存活。
