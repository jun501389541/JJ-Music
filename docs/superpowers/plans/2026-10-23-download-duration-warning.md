# 下载时长差异提示实施计划

> 使用 superpowers:executing-plans 顺序执行；不委派，不自动提交或发布。

**Goal:** 下载所得音频时长与目录明显不符时，在现有下载警告中呈现可核对的事实。

**Architecture:** 复用 DownloadManager 下载后已经执行的 music-metadata 解析及现有 warnings 展示、持久化。完成仍表示音频成功保存，入库规则保持原状。不新增请求、依赖或全曲解码。

**Tech Stack:** TypeScript、music-metadata、Node 离线生产模块测试。

## 证据与规则

上一轮 24 个真实组合有三个 QQ 结果完整传输并成功解码，但音频 60.004 秒、目录 256 秒。LX 当前只返回 URL，没有供应用保留的试听标记；播放器进度使用媒体实际时长。

目录 interval 按已有 mm:ss 契约严格读取；未知、无效或零时长不猜测。媒体时长须有限且大于零。差异超过 max(5 秒，目录时长的 5%) 时，提示媒体与目录各多少秒，并请用户核对音源与版本。此阈值为本次实现采用的保守默认，避免把微小编码或目录取整差异提示为异常。较短和较长均提示。

元数据时长不等于完整解码证明，也不能单独证明试听、歌曲身份或母带版本。正常通过不会显示“全曲已验证”。不自动换源、不阻止保存或入库、不修改第三方脚本。
