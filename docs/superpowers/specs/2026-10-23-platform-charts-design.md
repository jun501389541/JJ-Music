# F1：网易云与 QQ 音乐榜单浏览和播放

状态：用户已确认网易云与 QQ 音乐双平台范围，并以“开始实施”批准本设计。2026-10-24 已实现并通过自动验证；真实响应、离线和人工验收边界见开发记录。

## 依据与现状

播放收敛 A–C、在线可靠性 OR0–OR7 及后续工程修复已完成；OR8 的真实源/听感边界继续保留。本地缺失文件重新定位已合并本地 main `d2840d7`，本次不重复开发或改变其交付范围。

PRODUCT_RULES 将榜单排除在上一轮播放收敛之外，旧研究方案的“按音源浏览榜单”已被平台目录与音源解析分工取代。实施前 `/charts` 跳转到发现页，LibraryRouter 的旧榜单能力不可用。F1 新阶段采用平台目录适配器提供榜单和曲目；LX 音源只负责现有播放地址解析，不新增 JJ 脚本协议。

## 首版范围

- 同时提供网易云、QQ 音乐榜单列表和榜单曲目；无需平台账号登录或可用音源即可浏览。
- 侧栏增加“排行榜”，`/charts` 进入新页面；顶部切换平台，保留各平台当前选择及已加载页面，不把不同平台相同 ID 当成同一榜单。
- 展示榜单名称、可获取的封面、更新时间/周期及上游提供的简介。未知更新时间或总数不捏造。
- 选择榜单后展示标准在线曲目，沿用现有曲目菜单、收藏和播放流程。普通收藏只改变“我喜欢的”，不自动保存整个榜单。
- 本阶段不做订阅、定时同步、榜单历史、账号体系、评论、跨平台榜单混排或完整榜单一键导入。

## 播放与分页

- 曲目双击：以当前已加载曲目顺序建立常规队列，从所点位置开始，后续按现有播放模式运行；不会按搜索单曲试听处理。
- “播放已加载的 N 首”按钮明确展示范围，只播放当前已加载结果，不为了播放全部后台抓取剩余分页，也不提前收集未播放条目。
- 播放仍要求对应可用音源，失败走现有解析/降档/错误反馈规则，不把目录可浏览当成音源可播放。
- 采用每页 20 首，用户手动加载更多，首版上限 500 首；达到上限明确提示“仅展示前 500 首”。这两个数是本阶段提出的默认值，仍须按实际接口契约实现，不借用旧方案未经验证的 5000 首上限。
- 上游返回周期或版本字段时，在分页中携带并核对；切换周期、平台或榜单后旧在途结果不得追加到新列表。分页失败保留已加载内容并允许重试，不将部分结果宣称完整。

## 请求、缓存与错误

- 复用既有受限 HTTP、响应体上限、请求预算、取消、错误分类、健康键和诊断脱敏。每个平台增加独立的榜单列表/曲目能力，不与播放地址解析共享熔断状态。
- 复用 ResourceCache 的合并请求和最后订阅者取消，缓存键包含平台、榜单 ID、周期/页号、适配器修订；不缓存播放 URL。新缓存纳入既有容量预算与清理入口。
- 保留最后一次合法缓存；刷新失败显示旧数据及过期/失败提示，首次失败与合法空结果分别显示。强制刷新也遵守真实 Retry-After。
- 首版不增加登录、Cookie 导入或第三方中转依赖。网易与 QQ 的实际公开页面/响应契约须分别核实，接口失效时保留可解释的失败状态，不硬编码歌曲来冒充成功。
- 主进程只接受受支持平台、受限榜单 ID 和页号；不接受渲染进程指定请求地址。封面沿用现有平台域名限制。

## 兼容性

新增明确的平台榜单契约，不将旧 providerId 误当平台 ID。旧 JJ-only 榜单入口继续可解释地不可用，避免恢复已经退役的音源能力；现有歌单导入和刷新不改变。

无用户资料格式迁移；只新增可丢弃缓存及页面状态。更新 PRODUCT_RULES 中 F1 本阶段边界，保留旧阶段排除范围的历史说明。
