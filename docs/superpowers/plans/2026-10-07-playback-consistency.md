# JJ Music 播放行为收敛与日常体验开发规划

日期：2026-10-07。状态：供分派和执行的规划；尚未实施。

上游：[产品与播放开发规则 1.0](../../PRODUCT_RULES.md)。产品行为以该规则及后续用户修订为准。本规划只落实既定方向，未决参数通过决策任务收敛，不能由执行者静默决定。

本规划依据本轮项目分析及已保存的规则编写。编写时 GraphFlow 返回 `Transport closed`，本地命令执行返回 `setup refresh had errors`，未完成新的源码和脚本复核。本文中的文件为已核实过的查找入口，函数名和具体改动范围须在 E0 重新确认。本文不声称测试、构建或图谱同步已经通过。

## 1. 执行目标与范围

交付可供作者日常使用的播放器：本地和在线路径独立，点歌与队列可预期，实际播放后收集，在线解析遵循音质优先，界面能说明真实状态。

按 A、B、C 三阶段推进，每阶段验收后再扩大范围。复用现有实现，围绕受影响流程改造，不整体重写播放器。榜单、评论、账号同步、完整 JJ 插件协议、交叉渐变不纳入本计划。

本文件的“部署任务”指分派开发工作。执行本计划不自动授权发布软件、操作线上服务、合并分支、执行第三方脚本或修改用户真实曲库文件；相关动作按后续用户授权执行。

## 3. 所有任务共同遵守的约定

1. 先读上游规则，再按任务编号开展。GraphFlow 可用时先调用上下文；变更后更新索引。不可用时记录错误并使用必要的定向源码读取，不伪造同步成功。
2. 先检查工作区和现有用户修改。最近一次核实存在 `tools/probe/clean-profile-sources.mjs` 的未提交改动，这只是历史提示；必须重新检查，保留所有不属于本任务的改动。
3. 确认失败场景与预期行为后，再改实现。对队列、解析顺序、取消、收集和迁移编写有意义的行为测试；不要求给简单文案或文档修改添加测试。
4. 使用当前 `package.json` 和现有 runner 的真实命令。不得猜测 npm 脚本、创建绕过现有测试框架的重复 runner，或把停用的旧测试当成有效验收。
5. 网络、音源和文件操作通过可控样本覆盖主要分支；真实兼容测试另外记录，模拟成功不能证明真实平台可用。禁止提交凭据、用户曲库或未经脱敏的第三方响应。
6. 改持久化结构前设计旧数据读取和迁移，先用复制的资料目录验证。原条目、列表顺序与音源私有数据不能因字段重命名被丢失。
7. 每项运行针对性测试和受影响的类型检查；集成门槛运行当前项目要求的构建、测试与相关检查。失败时记录原因，不能删除失败测试来宣称通过。
8. 未决事项会改变本任务外部行为时，先形成具体选项与推荐方案，由用户决定；同时可完成不依赖该决定的阅读、设计和样本准备。

## 5. 阶段 A：统一点歌、队列与收集

### D-A：落实阶段 A 未决边界

在编码前确定：

| 事项 | 推荐方案或需要提交的设计 | 影响 |
| --- | --- | --- |
| 单曲试听与循环模式 | 推荐试听结束停止；历史快照保存原队列模式，恢复时恢复。尚未获最终确认 | A1、A4 |
| 队列快照 | 先复用现有容量，明确保存顺序、位置、模式及是否恢复进度；明确列表改变后的快照行为 | A1、A4 |
| 实际播放确认 | 根据现有引擎事件和播放代次设计，证明未播放和旧请求不会触发收集 | A2 |
| 失败后的动作 | 明确单曲与列表遇失败是否停止、跳曲或等待用户；不能擅自复用 LX 默认 | A2、A4 |
| 在线设置 | 复用已有目录授权，不静默开启网络；明确关闭时缓存可见性和旧设置迁移 | A3 |
| “播放全部”的范围 | 明确搜索当前加载结果与保存列表的范围；按钮文案与行为一致 | A1 |

交付：决定写入任务记录，并同步规则第 9 节及必要验收项。提交推荐不等于用户已经确认。

### A1：搜索单曲队列与音频路径独立

规则：SRC-01、QUE-01、QUE-02、QUE-03。验收：V01、V02、V17、V18，以及单曲结束和历史快照场景。

优先文件：搜索页面、播放器 store、现有队列历史模块、相关设置入口。具体位置由 E0 确认。

步骤：

1. 建立本地/在线双击搜索、明确列表播放、队列被替换的行为测试。
2. 将搜索双击统一为传入单条歌曲；保留原队列历史。普通歌单和收集箱仍使用列表队列。
3. 去掉在线解析中的本地同曲自动播放。处理相关设置的展示与兼容读取，旧 `preferLocal` 值不能重新启用已取消行为。
4. 保留本地文件缺失的准确反馈，不增加静默在线兜底。
5. 验证模式和快照遵循 D-A，完成针对性检查和试听记录。

过渡说明：旧的“点击时加入收集箱”会在 A2 修正；A1 交接必须指出这一差异。A1 不作为完整阶段发布验收。

### A2：统一播放确认、收集与取消

规则：COL-01、COL-02、PLY-01、PLY-02。验收：V04、V05、V06、V11、V18。

优先文件：播放器 store、音频引擎事件接入、各页面播放入口、播放列表持久化服务。

步骤：

1. 覆盖解析成功但未播放、播放失败、A/B 请求乱序、重复事件和歌单逐首开始播放的测试。
2. 在统一播放流程接入已决定的实际播放确认，按当前播放代次收集原在线条目。
3. 删除页面内的提前收集逻辑，核对所有在线播放入口，不只修改搜索页面。
4. 按原平台和原生 ID 去重，保持已有位置；不收集本地条目和实际换源条目。
5. 新播放意图使旧请求失效；旧歌词、封面、URL、播放状态与收集结果不得污染新歌曲。支持取消的调用应传播取消信号。
6. 收集持久化失败单独反馈，保持已开始播放的音频；按确认方案提供恢复或重试。

验收补充：直接调用业务入口的测试和页面手工测试均通过；不能用 `playQueue` 返回成功或得到 URL 代替实际播放事件。

### A3：目录与音源解耦

规则：SRC-02。验收：V03，以及在线关闭、平台独立失败、音源停用后的目录操作。

优先文件：`platform-registry.ts`、搜索/资料路由、主进程 IPC、搜索和歌单导入界面、音源状态展示。

步骤：

1. 覆盖“目录授权开启 + 零音源”“某平台无目录能力”“目录关闭”的能力矩阵。
2. 将目录注册表依据改为目录授权和应用适配器能力；音频能力另依据健康音源声明。
3. 搜索、浏览、导入不要求可用音源；播放和下载检查解析能力并给出正确引导。
4. 排查详情、歌词、封面、热词、聚合搜索及缓存路径是否仍被音源准入错误拦截；不为尚未实现的平台凭空声明能力。
5. 验证音源导入、停用、崩溃和更新只影响对应解析状态；用户关闭在线能力仍阻止需授权的网络访问。

验收补充：没有音源时本地功能完整可用，且在线目录没有误显示“平台无结果”。

### A4：队列恢复与错误反馈

规则：QUE-03、PLY-01、PLY-02。验收：V12，加历史队列恢复、失效文件和在线失败场景。

优先文件：播放器会话/历史队列逻辑、`App.vue`、队列面板、反馈文案。

步骤：

1. 测试恢复队列但首曲失败、缺少文件、没有音源、恢复后立即点另一首。
2. 分离队列恢复结果与播放结果；避免下层吞掉错误后上层仍提示播放成功。
3. 准确展示加载、解析、播放、暂停和失败状态，按 D-A 处理失败后的后续动作。
4. 恢复不会隐式恢复不兼容来源或重复收集；新队列结束不会自动回到历史队列。

### G-A：阶段 A 通过门槛

执行 V01–V06、V11、V12、V17、V18 与 D-A 增补案例。运行 E0 确认的类型、构建、相关测试和仓库要求的检查；不遗漏在线开关与现有 IPC 约束的回归。

由作者实际完成“本地单曲 → 在线单曲 → 收集箱 → 恢复旧队列 → 快速切歌 → 失败重试”的日常操作。记录与预期不同的行为，先修阻碍使用的问题再进入 B。未完成的真实网络验证或既有失败必须列出，不能用整体“通过”掩盖。

## 6. 阶段 B：统一换源、音质与版本

### D-B：明确解析策略与兼容约束

决策内容：档位顺序和允许范围；音源优先级；旧 `providerId` 与私有参数兼容；同版本匹配阈值及资料缺失处理；单次请求、限流重试与总等待预算；缓存失效；音频检测范围及不符后的处理。

执行者必须给出具体方案和可验证样本，由用户确认会影响听歌结果的取舍。已经确定的目标档位优先与自动向下降级不得重新变成“平台先降级”。匹配不确定不自动播放是固定约束。

### B1：区分原歌曲与本次播放资源

规则：SRC-03、COL-02、AUD-03。验收：V06、V10。

优先文件：共享类型、播放器解析结果、IPC、播放详情、条目持久化与 URL 缓存。

步骤：

1. 定义原条目与播放资源的契约，保持原平台歌曲身份，独立保存实际目标平台/歌曲、音源身份、解析档位和检测信息。
2. 保持列表、队列和收集引用原条目；换源状态只附着于本次播放，不覆写原歌曲资料。
3. 设计旧条目、音源绑定与缓存兼容读取，用复制的旧数据验证。
4. 测试换源成功、再次播放、重复收集、应用重启与音源停用；验证实际来源显示准确。

### B2：实现同版本候选匹配

规则：AUD-02、SRC-03。验收：V09，加歌手顺序、分隔符、标点、资料缺失与多个候选。

优先文件：播放器中的 `sameRecording` 和跨平台搜索；需要时将匹配规则提取为可独立测试的模块。

步骤：

1. 建立正反样本：同录音不同写法，以及 Live、伴奏、翻唱、Remix、同名异曲。
2. 按 D-B 规范化资料、识别版本、排序候选；搜索同时利用歌名和歌手，明确分页或候选上限。
3. 区分高置信度、资料不足和确定不匹配；只让满足确认条件的候选进入自动解析。
4. 将人工选择作为明确决定的可选范围，不能用“不确定时随便选第一项”充当兜底。

验收：允许合理资料差异，同时反样本不被自动替换；记录启发式匹配的限制。

### B3：严格解析与音质优先调度

规则：AUD-01、AUD-02、SRC-01。验收：V07、V08、V09。

优先文件：`SourceEngine.getMusicUrl`、主进程解析 IPC、播放器解析流程、共享结果/错误类型。

步骤：

1. 先测试严格档位请求不降级、缺档位时可跳过、兼容音源筛选及绑定限制。
2. 将低层接口改为单次明确平台/音源/档位的尝试；复用现有严格能力时检查整条 IPC 链路，不能只改参数默认值。
3. 在一个编排位置实现“原平台本档 → 其他平台同版本本档 → 下一档”，避免播放器和源引擎各自降低音质。
4. 兼容候选按 D-B 顺序尝试；不强行跨越不兼容私有数据或让同一失败候选无限循环。
5. 记录可解释的尝试结果，用可控响应断言先后顺序：原平台低档可用、别的平台目标档可用时必须选目标档。

验收：原平台目标档可用时不必跨平台；原平台低档不能抢先终止目标档搜索；不会向上提升超出用户目标，也不会自动使用本地文件。

### B4：等待预算、缓存与音质显示

规则：AUD-01、AUD-03、PLY-01、PLY-02。验收：V08、V11、V16，加过期地址、限流、停用源与缓存命中。

步骤：

1. 按 D-B 设定总等待、单次超时和限流重试，用可控时钟验证停止和取消，不依赖长时间真实等待。
2. 缓存分清目标档位与成功档位；缓存低档位不能绕过高档位优先。明确音源版本变化、停用、地址失效与候选变化的失效规则。
3. 失败后仍保留原条目，反馈匹配失败、音源失败、档位失败和等待结束的区别。
4. 展示目标档、解析档与可测规格；未检测不宣称真实音质已验证。按 D-B 处理检测不符。

### G-B：阶段 B 通过门槛

运行阶段 A 回归、V07–V10、V16 及 D-B 样本。模拟验证解析次序、限流、取消和缓存；使用用户允许的音源及脱敏资料做真实兼容测试，记录音源版本、平台和失败条件。

真实平台暂不可用时，能完成模拟验证并报告限制，但不能宣称真实播放成功率或“完全兼容 LX”。

## 7. 阶段 C：完善日常体验

### D-C：明确下载和过渡细节

确认下载目录与曲库接入方式、覆盖和重名处理、下载降级是否需要确认、入库失败恢复；确认淡入淡出的默认开关、时长、设置范围及快速操作优先级。下载不继承在线播放的静默降级规则。

暂停/恢复 150 ms、启动与手动切歌 300 ms 为此前建议的试听起点，需通过试听决定最终值。自然结束、拖动进度和静音是否增加过渡不能静默扩展。

### C1：下载完成后可靠入库

规则：SRC-04。验收：V13，以及重复入库、下载失败、保存路径变化、已有扫描目录。
