# 队列保存、循环时间输入与睡眠渐弱设计

日期：2026-10-27。状态：用户批准后已按顺序实现；独立最终审查的两项问题修复并复核关闭，完整自动验证通过，现已获提交推送授权，尚未发布。

用户已选择三项全部按顺序开发：①当前播放队列保存为新歌单，②A–B 循环直接输入时间，③睡眠结束前逐渐降低音量。下列具体边界与默认值已随完整设计获用户批准。

延续[播放扩展设计](2026-10-26-playback-expansion-design.md)、[手动切歌渐变设计](2026-10-26-manual-crossfade-design.md)及[项目产品规则](../../PRODUCT_RULES.md)。与旧文档冲突处仅在本设计获批后生效。

## 目标与范围

保存临时整理的播放顺序，准确输入片段端点，避免睡眠结束时突然断声。沿用 Electron/Vue/Pinia、现有普通歌单和双通道 WebAudioEngine；不引入依赖，不改个人音乐文件。保留已推送 `codex/manual-crossfade` 的功能与提交。本批提交、推送、合并、发布均待另行请求；真实音源和人工听感继续单独验收。

三项按上述顺序实施，完成自动验证及独立最终审查后交付。第一项只保存当前队列，不扩展历史页或保存搜索筛选结果；第二项不持久化片段、不增加书签；第三项不新增系统关机、音频响度标准化或定时任务恢复。

## 当前实现与实现方式

- `PlaybackPanel.vue` 区分当前队列和历史页，搜索仅影响显示，没有整队列保存入口；`track-actions.ts` 的新建歌单再加曲是两次写入，不足以满足本功能失败原子性。
- `PlaylistStore` 已有串行 `mutate`、失败回滚与原子文件保存。复制/合并 `createDerived` 需要来源歌单版本校验，不能伪造一个队列歌单身份绕过该约束。
- player 已有会话内 A/B、手动交接准备/提交/回滚及睡眠立即/整曲停止；现有端点动作仅使用当前播放进度。
- WebAudioEngine 的每通道交叉渐变、共享音量/静音、短过渡增益分别有独立职责，睡眠渐弱必须有自己的共享增益。

推荐延伸以上结构：为歌单增加有界的队列快照创建事务；新增原子设置两个循环端点的 player 动作；为 WebAudioEngine 增加专属睡眠增益节点及窄接口。复用既有对话框样式和播放菜单，不重做面板布局。

可选方案及取舍：新建空歌单再添加曲目改动少，但失败可能留下空歌单；一次事务创建可整体回滚，采用后者。逐个更新 A/B 会暴露中间无效状态，采用同时校验同时替换。复用音量滑块或短过渡增益会与用户设置、暂停恢复竞争，采用独立睡眠增益。以上为基于当前代码的实现建议，具体函数名与组件拆分交实施者决定。

## 1. 当前队列保存为新歌单

### 用户操作

当前队列页增加“保存为新歌单”，空队列禁用；历史页不出现该入口。搜索筛选时仍保存完整当前队列，按钮说明及对话框明确“保存完整队列”，显示输入数量、去重后数量与歌单名称输入框，确认后保存。默认名称为“播放队列 YYYY-MM-DD HH:mm”，使用本机显示时间；用户可修改。

点击入口时捕获完整当前队列的独立快照，后续排序、换队列或切歌不修改这个快照。确认保存的是打开对话框时的内容，取消不写入。等待期间只允许一次提交；成功刷新歌单列表并提示名称/首数，不开始播放或跳转页面。

### 数据与失败

新建普通本地歌单，保留输入首次出现顺序，按 `playlistEntryKey` 完整身份去重；本地/在线及不同平台同 ID 仍是不同条目。保留既有音源绑定和曲目元数据；不保存本次解析 URL、播放进度或会话音频状态，不设置远程来源关联。

主进程接收名称和曲目快照，通过现有 IPC 曲目校验/持久化清洗规则构造允许字段；脚本封面 data URI 按既有规则剥离。该动作只保存引用，不播放、联网、读取任意文件或把在线条目替换为本地条目。合法但当前缺失的本地引用可以保存，继续由现有缺失文件流程处理。

边界：名称 trim 后 1–4096 字符，不接受 NUL；原始输入 1–50000 首且 JSON UTF-8 不超过 20MiB，在主进程深拷贝前检查；字段及身份无效、超限整批拒绝，不截断。renderer 计数仅用于提示，主进程重新计算去重数量并返回结果。

`PlaylistStore` 新增专门的队列快照创建方法：复用 `mutate`，同一次变更分配新 ID/末尾位置并写入列表及曲目；写盘失败恢复事务前状态，不产生可见空列表。不得放宽既有复制/合并的来源 CAS 校验。并发其他歌单编辑通过既有串行链保存，不回放旧全量快照覆盖较新数据。

## 2. A–B 循环直接输入时间

播放更多菜单的“A–B 片段循环”增加“输入 A/B 时间…”。当前已加载曲目须有有限正时长，且不处于睡眠到点等待；与既有端点入口相同的可用性规则。对话框显示歌曲名、时长、A/B 输入和“确认后启用片段循环”。已有端点用其原值，否则 A 默认 0、B 默认曲长；曲长不足 1 秒时提示不可设置。

接受阿拉伯数字的秒数（如 `90.5`）、`分:秒`、`时:分:秒`，小数最多 3 位，仅允许最后一段有小数。带冒号时秒段须小于 60，三段格式的分钟须小于 60；两段格式的分钟可超过 59。允许首尾空格；拒绝空值、负数、指数、非数字、非有限值、多余冒号与不合法段值，不猜测模糊输入。格式化不得因显示舍入把端点推出曲长。

确认时 player 一次校验并设置两端点：`0 <= A < B <= 当前实际时长`，且 `B-A >= 1 秒`。对话框绑定打开时的完整歌曲身份及播放代次，曲目或代次变化后确认拒绝，时长变化也按当前实际时长复核。输入错误、睡眠等待或陈旧上下文均保留原 A/B 和播放状态。

校验成功才取消未发声交接准备；已发声交接收束到已提交曲目，然后原子替换端点并启用。当前进度在 `[A,B)` 外则定位 A，在区间内保持；暂停状态始终不自动播放，不新增最近播放/收集事件。取消对话框不修改端点或交接。既有清除、暂停循环、手动定位、睡眠优先级及失败回滚规则继续适用。

## 3. 睡眠结束前逐渐降低音量

### 设置与时机

睡眠菜单增加“结束前渐弱”，可选关闭、5、10、20、30、60 秒，默认关闭。选择非零项启用；时长、睡眠模式和定时器均只保留当前会话，不写入设置或恢复任务。更改渐弱时长不重置睡眠倒计时，也不修改用户音量/静音。

- 立即停止模式：距离既定停止时刻剩余 `R` 秒时，睡眠增益为 `clamp(R / F, 0, 1)`，F 为所选渐弱秒数；最后 F 秒由 1 线性降到 0。若启用时距停止不足 F 秒，按实际剩余比值进入渐弱，经短平滑避免阶跃；停止时刻不后移。
- 播完整曲模式：到点前保持睡眠增益 1。到点沿用现有规则退出 A/B 并等待已提交整首曲目；仅等待状态中按 `(duration-currentTime)/rate` 的剩余墙钟秒数计算相同增益。若到点时剩余不足 F 秒，则从对应比值渐弱；既有未知时长到点立即停止规则不延后。
- 关闭渐弱或取消/重设定时恢复睡眠增益 1，使用短平滑。到点后切到立即停止模式仍立即停止。整曲等待中有效用户选歌取消等待及渐弱；未到点换曲保留原倒计时和即时模式渐弱。

倒计时在暂停/缓冲时仍按墙钟前进：立即模式在既定时刻停止，不主动恢复播放。整曲模式暂停/缓冲时媒体时钟不走，增益随媒体剩余时间保持；恢复、改速、定位或时长更新时重新计算。定位到更早位置可相应回升增益；不改变整曲结束停止语义。渐弱状态在现有定时状态区域显示，保留取消入口。

### 音频及生命周期

在共享音频输出路径增加睡眠 GainNode，使两通道、EQ、用户音量与短过渡最终乘以睡眠增益；不复用每通道交叉渐变参数或 `GainTransition` 自动化。引擎提供有限 0–1 的睡眠增益接口，统一短平滑并保存初始化前的值；不调用 `setVolume` 模拟渐弱。现有生产引擎实现该接口；不具备接口的测试/其他引擎不宣称支持渐弱，不回退修改音量。

player 负责有界节拍更新及到点检查（建议 100ms），同时在进度、播放状态、模式、改速与定位等关键变更后更新；闲置时不保留节拍。后台定时器延迟后按实际时刻计算，过点先执行停止，不重放旧渐弱任务。

所有异步回调绑定定时器代次；取消、重设、stop、dispose 后旧回调不能写增益或停止新播放。stop 先消除可发声音频再复位睡眠增益，避免末尾脉冲；dispose 释放节点与定时资源。准备/交接/回滚均保留当前睡眠控制，不从旧曲快照恢复睡眠增益。无论双通道交叉渐变、短暂停/恢复还是快速取消，音量滑块和静音状态不变。

## 接口、兼容与错误反馈

队列保存新增有界共享请求/结果、IPC 通道、preload 桥、主进程处理及 renderer store 动作；复用现有歌单文件格式，无迁移。IPC 必须在主进程再次校验。保存失败在现有通知显示原因，允许用户重新尝试；成功不改队列、历史、当前曲或收藏。

循环新增纯时间解析/格式化帮助函数及 player 原子端点动作，对话框复用现有模态约定。睡眠新增会话状态与引擎专属增益能力，不新增 Settings 字段。具体模块名、错误类型与界面细节由实施者沿用项目习惯，但不得弱化边界或引入新依赖。

## 待批准的主要取舍
