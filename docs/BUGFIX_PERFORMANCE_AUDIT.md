# 项目复查与性能优化（2026-09-17）

本轮检索覆盖主进程、渲染进程、共享类型及测试工具，重点检查播放队列、设置/历史保存、文件夹扫描、搜索、歌单、封面主题和 IPC。修改保留发现音乐、全局搜索、播放页 EQ 与队列侧栏。此报告记录已定位并修复的问题，不意味着所有外部音源或硬件环境均无故障。

## 修复

| 问题 | 修改与验证 |
| --- | --- |
| Vue 响应式文件夹数组不能直接通过 IPC 克隆 | 设置更新先生成普通数据快照；单测验证 reactive 对象与调用后数组修改，真实窗口验证文件夹设置保存 |
| 设置快速更新可能并发回写旧值，且大量写盘 | 新增串行合并写入器，立即反馈界面，在旧写入完成后仍保留更新的输入；失败回退已提交值、提示错误，后续保存可恢复 |
| 每次保存播放历史等设置都会重设音质，清空地址缓存 | 分离设置监听；相同音质不再清缓存，相同 EQ 增益不再重设滤波器；验证重复播放只解析一次 URL |
| 批量追加队列包含重复歌曲；立即播放已在队列中的歌曲无效 | 批内去重，并正确定位现有歌曲；新增回归测试 |
| 移除当前歌曲后显示另一首未播放的歌曲或索引越界 | 停止播放并将当前索引置为 -1；下一首仍可正常开始 |
| 快捷键快退可使界面出现负时间；非法数值污染播放状态 | 限制定位范围，忽略 NaN/Infinity，校验播放速度及 EQ 增益 |
| 快速连续点击喜爱，两次都执行添加 | 收藏修改串行处理；两次切换恢复原状态，删除重复的歌单/收藏查询 |
| 并发初始化重复读取数据并注册事件 | 合并初始化 Promise；失败后可重试，验证仅注册一次监听 |
| 父目录和子目录重复扫描、移除父目录丢失子目录中的曲目 | 扫描同一路径只计一次；保留仍被其他配置目录覆盖的歌曲，验证重载后仍存在 |
| 添加文件夹后，保存相同目录配置又触发扫描 | 按曲库的实际目录集合判断是否需要执行添加/移除 |
| 歌单详情在收藏/添加操作后仍展示旧内容 | 监听歌单刷新，加载加代次校验，忽略过期或卸载后的结果 |
| “我喜欢的”显示删除按钮但后台禁止删除 | 隐藏内置歌单删除入口；歌单和音源删除使用应用内确认框 |
| 慢封面加载覆盖新封面或用户指定的强调色 | 封面取色请求过期后不应用；自定义强调色同步更新派生颜色 |
| 虚拟列表缩短后可能落在不存在的行上 | 限制虚拟起始行，换列表时重置选择锚点；空选择不遍历整张列表 |

## 性能改动与测量

- 本地搜索索引随曲库元数据变化重新构建；查询复用正规化后的文本，匹配项排序前只计算一次分数，复用 `Intl.Collator`。
- 最近播放使用曲目 ID 索引查找，不再对每条历史扫描整张曲库。
- 插播批内去重从嵌套查找改为 Set；主进程按 ID 查询避免先复制整个曲库数组。
- 设置更新合并正在等待的字段，减少 IPC 和 JSON 写盘次数；没有额外定时延迟，初始写入在微任务中提交，返回的 Promise 等待对应数据保存完成。

`node tools/benchmark-ui.mjs` 使用 10,000 首合成曲目、每轮 50 次查询、3 轮中位数，并逐条校验优化前后结果一致。本机一次测量：

| 项目 | 优化前 | 优化后 |
| --- | ---: | ---: |
| 50 次搜索中位耗时 | 217.40 ms | 45.05 ms |
| 搜索索引首次建立 | — | 2.71 ms |
| 101 次快速设置更新的 IPC 写入数 | 101 | 2 |

搜索专项约快 4.83 倍。此为合成数据基准，真实收益随曲库、关键词和机器变化；没有将它等同于整个应用的性能提升。
