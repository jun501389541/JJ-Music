# OR3 — 歌词与封面缓存

实施：2026-10-15 开始，2026-10-16 完成离线交付。依据原设计 OR3 与 [实施计划](../../superpowers/plans/2026-10-15-online-reliability-or3.md)。后续 OR4–OR8 未计为完成。

## 本期行为

- 在线歌词、目录封面、脚本封面：30 天新鲜，180 天最长展示。失败可保留仍允许展示的旧成功值与错误；取消、过期、源版本变化不会被记成新成功。
- `OnlineAssetCache` 复用上期 `ResourceCache`；歌词持久化桶上限 16 MiB，单条规范化数据 2 MiB；封面字节 192 MiB、单张 8 MiB，索引另限 2 MiB，只存 hash/MIME/size，不把图片塞入 JSON。
- 二进制仅放 `library/covers/online-cache-v1/<sha256>.bin`，索引和歌词在 `cache/online/v1/`。封面回收仅触碰独占目录的受控 hash 文件；不会扫描共享封面目录、下载目录、用户歌单或待写入队列。
- 用户保存和标签写入仍使用现有资产服务，得到独立副本；自动缓存回收不删除这些副本。既有历史资产不做猜测迁移或删除。
- 歌词去除非契约字段，拒绝 HTML、控制字节、空和超限内容；图片校验 MIME、文件签名和 SHA-256。签名校验不等于完整解码验证；纯合成 UI 另验证了一张实际 PNG 可解码。
- 同键请求合并、每消费者独立取消，最后消费者撤销底层请求；清理代次、源版本检查和现有请求截止时间阻止迟到结果回填。
- 资料请求使用 10 秒总预算、5 秒单次上限；源引擎负责的重试不会被上层再次包一轮。在线歌词来源顺序的外层预算仅负责总截止，不负责额外重试。

## 生产接入

| 路径 | 本期变化 |
| --- | --- |
| 在线歌词来源顺序 | 平台和脚本分别建键；未绑定脚本条目使用可用候选的稳定身份/内容版本集合指纹，绑定条目保留绑定。 |
| 本地歌词查询/候选 | 平台歌词读取缓存；原歌曲匹配规则保留，未合并不同条目。 |

| 本地解析内存缓存 | 自动在线结果服从资源时间；用户已确认的待写入选择独立保留，不被自动缓存清理。 |
| 手动重搜/指定歌词来源 | 刷新意图传至资源缓存 force，重新获取同一候选歌词；普通读取仍命中新鲜缓存。 |
| 在线播放补全 | 平台与脚本封面返回受控 data URL；已有手工封面和待写入选择保持优先。失败不让 Chromium 再用原 URL 静默重复请求。 |
| 精确艺术家/专辑封面 | 读取自动字节缓存并返回 data URL，不再为每个自动详情图片无界复制到用户共享资产目录。 |
| 标签匹配封面 | 复用平台缓存字节；既有 withCover/overwriteCover/dryRun 判定继续控制是否获取/写入。 |
| 设置与退出 | 复用现有资料缓存开关/清理，退出 flush；过期歌词来源标签显示“资料较旧”。 |

搜索列表缩略图、歌手肖像、下载任务内部的独立封面获取和用户歌单封面仍沿用各自既有路径。本期不将它们声称为已统一完成的新缓存接入；歌单相关变化继续归 OR4，跨模块总容量协调与更新事件按后续阶段接续。

## 独立复核与修正

只读 reviewer 没有执行真实脚本、联网或整套构建，提出 3 项 Important，无 Critical/Minor；本期均修正：

1. 配额原先只计算紧凑 entries，格式化落盘后可能超过读入上限。新增近容量回归，实测修复前 4096 字节配置写出 5275 字节；现在按实际包装与缩进后的字节数淘汰，重启仍命中最新记录。
2. 显式重搜没有传递 force。纯合成 Electron 探针先复现旧歌词，再证明普通命中与一次显式合成刷新分别返回旧/新内容。
3. 拒绝链接缓存目录后仍保留该磁盘路径。现在永久降为内存，并在后续磁盘操作检查目录；put/read/clear 不再经链接触碰外部文件。

另补齐了首次消费者取消不能影响其他消费者的回归，以及自动缓存清理保留待写入选择的回归。
