# JJ Music 产品与播放开发规则

日期：2026-10-07。版本：1.0。

状态：依据访谈及用户确认建立的开发基线。阶段 A–C 已实现并通过自动检查；真实人工验收状态见[统一清单](development/2026-10-12-final-manual-acceptance.md)。本规则说明目标行为，不替代真实听歌、音源兼容和日常使用验收。

分派与执行入口：[播放行为收敛与日常体验开发规划](superpowers/plans/2026-10-07-playback-consistency.md)。规划包含任务依赖、验收门槛、交接记录和可复制的执行说明。

后续专项：[在线资源可靠性开发设计](superpowers/specs/2026-10-15-online-reliability-design.md)（设计待评审）。覆盖缓存容错、错误分类、健康状态、更新和诊断；不替代现有播放规则或真实人工验收。

## 1. 目标、范围与文档优先级

优先满足项目作者自己的日常听歌习惯：本地和在线各自成立，共用稳定、可预期的播放体验。界面以 Salt Player for Windows 为参考，在线能力分工借鉴 LX Music；参考软件不自动成为功能验收标准。

第一阶段优先解决点歌、切歌、队列恢复、来源选择和在线失败处理。榜单、评论、账号同步、完整插件协议、交叉渐变不列入本轮播放收敛范围。

上述范围保留第一阶段的历史决定。后续批准的普通歌单批量改名与交叉渐变分别见第 18、19 节；交叉渐变默认关闭，与原有短过渡独立。

本文件是后续产品行为与播放规划的入口。同一事项与旧研究、实施计划冲突时，以本文为准；未涉及的安全、发布、更新与技术约束仍沿用原文档。后续用户明确修订可以取代本文，修订时须同步规则、验收案例和受影响计划。

本轮明确取代的旧要求：

- “搜索、歌词、歌单等全部由 LX 音源提供”：改为应用目录适配器与音源地址解析分工。
- “音源存在且健康才开放对应平台的所有目录能力”：改为目录能力与播放地址能力分别判断。
- “点击在线歌曲自动优先播放本地同曲”：取消，保持用户选择的本地或在线路径。
- “双击搜索先收集，再播放整个默认列表”：改为单曲队列，实际开始播放后收集。
- “某个脚本逐档降级成功即播放”：改为在目标档位尝试可用平台与音源，失败后再降低档位。

旧文档保留为历史：[完整音源方案](research/source-bound-online-capabilities.md)、[旧实施计划](research/source-bound-online-capabilities-plan.md)、[由 LX 音源启用在线能力方案](research/lx-gated-online-capabilities-executor.md)。

## 2. 核心对象与职责

| 对象 | 含义 | 负责什么 |
| --- | --- | --- |
| 本地曲库条目 | 一个可定位的本地音频文件及其资料 | 文件读取、扫描、标签与本地资源管理 |
| 在线歌曲条目 | 某个平台的原生歌曲 ID 及其资料 | 展示、保存、跨平台匹配的起点 |
| 在线目录适配器 | 应用维护的平台资料接口 | 搜索、歌单读取、歌词、封面及声明支持的详情 |
| 音源实例 | 用户导入的 LX 脚本及其声明能力 | 指定平台、指定档位的播放地址解析 |
| 保存列表 | 用户保存的歌曲条目集合 | 持久化内容和顺序，不决定每次播放的来源与队列 |
| 当前队列 | 本次播放的条目顺序、位置和上下文 | 下一首、上一首及本次播放范围 |
| 队列历史 | 被替换的队列快照 | 用户主动恢复之前的播放上下文 |
| 本次播放资源 | 为当前条目解析出的文件或在线地址 | 实际平台、音源、解析档位与可检测音频规格 |
| 在线试听收集箱 | 原默认列表的新语义 | 收集实际开始播放过的在线歌曲 |

职责划分不要求重写整个项目。实施时优先复用现有模块；页面表达播放意图，统一播放流程处理队列、解析、取消、播放状态与收集事件。

## 3. 来源、目录与资源规则

### SRC-01：本地与在线音频路径独立

点击本地条目只读取该条目的本地文件；点击在线条目走在线解析。同曲可同时存在于两边，互不覆盖、不自动合并。在线解析不把本地文件作为自动兜底。

本地文件缺失时必须准确提示，不能悄悄改播在线同曲。2026-10-23 已确认[逐首手动重新定位设计](superpowers/specs/2026-10-23-local-file-relink-design.md)：用户选新文件并预览确认后修复本地引用，保留收藏、歌单顺序、播放队列及恢复进度；不移动文件、不自动播放，不静默重定向待写入资料或旧下载记录。原文件可访问、目标已被其他本地记录使用或预览失效时拒绝；跨资料文件的中断须恢复后再开放写入。

### SRC-02：目录能力与音源能力分开判断

在线资料默认可用；搜索、资料浏览和歌单导入不要求已导入或启用音源。播放、下载时才检查相应的音源解析能力。

2026-10-08 用户明确取消在线目录授权弹窗和开关。目录适配器缺少能力、接口请求失败、没有搜索结果、没有播放音源须给出不同状态。一个平台故障不关闭其他平台。

不再读取 `onlineCatalogConsent` 和 `onlineCatalogConsentPrompted`，旧配置中的同意或拒绝均不影响目录能力。保存设置时移除这些退役字段。目录能力依应用适配器声明判断；在线播放仍依赖可用音源。

音源更新只影响它提供的解析能力，不能承诺修复应用目录适配器。第一阶段继续兼容现有 LX 协议，不要求另写完整 JJ 音源来获得搜索。

2026-10-08 用户修订：音源导入只接收单个脚本（明文 JS 或 `gz_` 编码），移除从 LX Music `user_api.json` 或 JSON 脚本数组批量导入的功能。文件选择、拖入、粘贴和链接导入遵循同一规则。保留既有音源的内部存储格式与读取能力，不迁移或清空已有音源。

同日音源管理界面修订：“全部启动”“全部关闭”收进“批量操作”菜单，增加“全部移除”。全部移除须展示数量并经用户确认，逐个停止和移除音源，部分失败时继续处理其余音源并汇总结果；取消不删除音源。无音源或正在导入/批量处理时禁用批量入口。文件导入按钮统一使用“本地导入”。

### SRC-03：原条目身份与本次播放资源分离

跨平台换源后，保存列表、收集箱和队列仍保留原来点击的在线条目。实际播放资源另行记录目标平台、目标歌曲 ID、音源身份与解析档位。自动换源不覆写原条目，也不产生新的收集箱条目。

基础去重身份为“原平台 + 原生歌曲 ID”。音源实例 ID 不能替代平台歌曲身份；私有参数与音源绑定信息仍需单独管理，不能把不兼容的私有对象盲目传给另一脚本。

### SRC-04：下载形成本地条目

下载成功后将文件纳入本地曲库，保留原在线条目。下载来源可作为可追溯资料，但不改变 SRC-01 的播放路径。不能只用“下载任务完成”推断“本地入库成功”；入库失败须单独反馈并允许恢复。

下载列表的音质回退交互与文件命名、保存位置在具体下载规划中确定，不从在线播放的自动降级行为推导出静默降级下载。

2026-10-12 D-C 已采用：沿用下载目录与同名编号保护，严格下载所选档位；入库失败只重试入库，不重新下载。仅移除下载记录保留本地歌曲；删除下载文件成功后同步清理对应曲库条目。移除与入库互斥，等待超时保留文件和记录。

### SRC-05：本地资料写入须明确

本地歌词、内嵌资料和用户管理的本地资源优先。在线补充缺失资源不等于切换音频来源，也不授权修改文件标签。需写入的在线歌词或资料先缓存，用户明确确认后写入。

## 4. 队列与收集规则

### QUE-01：双击搜索结果创建单曲队列

本地与在线搜索采用相同规则：双击一个结果，当前队列只包含这一条；被替换的队列进入已有队列历史。不会顺带播放其他搜索结果或整个收集箱。常规顺序播放下单曲结束停止，不自动恢复旧队列。

搜索双击建立的单曲试听结束后停止，不受全局单曲循环模式影响；全局模式保持原值。历史队列恢复时采用快照保存的模式。

### QUE-02：明确的列表播放使用列表队列

点击搜索“播放全部”，只以当前已加载结果顺序建立队列，不自动请求未加载的分页；界面须说明当前范围或数量。双击收集箱或普通歌单中的歌曲，以该完整列表顺序建立队列，从点击位置开始。在常规顺序模式下继续播放后续条目。

加载未完成、分页列表的“全部”范围在实现该入口前确定；不得把当前已加载页悄悄称为全平台结果。

### QUE-03：队列历史由用户主动恢复

替换当前队列不等于删除保存列表。历史队列不会因新队列结束自动恢复。恢复动作必须准确反映队列加载、曲目可用性和实际播放结果；设置了队列不能被当作已经播放成功。

历史最多保留 2 个不可变快照。每个快照保存队列顺序、名称、创建时间、当时的当前索引和播放模式，不保存精确播放进度；修改来源歌单不改变已保存快照。恢复快照时从当前索引对应曲目的开头播放。精确播放位置由 LastSession 单独负责。

### COL-01：实际开始播放后才收集

统一播放流程以当前播放代次 AudioEngine 发出的 `playing` 事件作为实际开始播放确认，并核对事件对应条目仍是当前条目且已加载 ID 相同。每个播放代次最多确认一次；确认后只把原在线条目写入默认收集箱。搜索单曲、播放全部、导入歌单和自建歌单均遵循该规则。

点击、获得 URL、建立队列或播放器进入加载状态均不算实际开始播放。排队但未播放的歌曲不收集；失败和取消的旧请求不收集。本地曲目不进入在线收集箱；自动换源时仍以原在线条目收集，不另建候选平台条目。最近播放记录继续独立维护。

### COL-02：去重不改变已有顺序

同平台同 ID 只保留一条，重复播放不移到顶部。跨平台条目保持独立，展示平台标识；不按歌名自动合并。本地播放不加入在线试听收集箱。

收集箱写入失败须与播放失败区分，不能为了写入失败而停止已经开始的播放。收藏、收集箱与队列的数据变更不得相互隐式传播。

## 5. 音质优先与跨平台换源

### AUD-01：由统一流程控制音质回退

先固定本次目标档位，再按下列顺序尝试：

1. 原平台上兼容该条目、可用的音源，严格请求目标档位。
2. 其他平台上可确认同一录音版本的候选，严格请求同一档位。
3. 本档位的可用候选均未成功后，降低一档，重复上述顺序。
4. 所有允许的档位与候选失败后，结束本次尝试并提供明确失败状态。

音质档位不得高于用户所选目标。缺少目标档位声明表示该候选不可尝试此档位，不是整首歌不存在。适配器与音源解析层只执行指定档位，不能在内部先降级成功后绕过统一顺序。已缓存低档位结果也不能冒充目标档位命中。

用户已选择自动降低音质以保证能播放；降低后须明确显示解析档位。2026-10-12 已确认：原平台优先，其他平台按 tx、wy、kw、kg、mg 稳定顺序；同平台沿用启用优先顺序。总解析预算 60 秒（初次重试共用截止时间），单次音源最多 20 秒；明确 HTTP 429 最多重试一次、等待 500ms。取消与超时均中止可取消的在途网络，不允许无限尝试。

### AUD-02：版本匹配先于地址解析

跨平台候选必须满足同一录音版本要求。歌名、歌手、版本标识、时长、专辑等资料共同作为依据；合理处理标点、合作歌手顺序和分隔符差异。

Live、伴奏、翻唱、Remix 等不同版本不能为了播放成功而自动替换。匹配不确定时不自动播放该候选。2026-10-12 已确认：两侧时长均有效且差不超过 5 秒；缺关键资料或明确版本冲突不自动匹配。重制、重新录制、特别版和明确的年份证据分别判断；每平台检查第一页前 20 条，最多保留 3 个候选。本阶段不新增人工匹配入口，不把资料匹配当作同一母带的保证。

### AUD-03：音质显示说明依据

分别保存目标档位、解析成功的请求档位，以及可检测到的编码、码率、采样率和位深。请求 FLAC 后得到 URL 不等于已经验证文件规格，更不等于证明音频制作来源。

未检测时使用“按 FLAC 档位解析”等准确措辞；已检测则展示检测结果。检测与请求不符时必须如实显示，不得继续标记为已验证的目标规格。2026-10-12 已确认：不增加开播前额外音频下载检测；在线资源无可信实测信息时明确标注规格未检测，不依据请求档位或输出设备规格填充真实音频信息。

## 6. 播放状态、错误与过渡

### PLY-01：所有入口共用播放流程

搜索、歌单、收集箱与历史队列只提交条目或队列意图。来源选择、换源、音质回退、请求取消、播放确认及收集由统一流程处理，页面不得分别实现回退和收集规则。

新播放意图生效后，旧请求的迟到结果不能覆盖当前歌曲、状态、歌词或封面，也不能写入收集箱。逻辑上使旧请求失效之外，可取消的网络或音源请求应实际取消。

### PLY-02：反馈必须对应真实状态

至少区分队列已设置、正在匹配、正在解析、正在加载、实际播放、暂停、失败。界面可简化展示，但业务层不能把这些状态混用。

缺少音源、目录失败、匹配失败、档位失败、地址失效、本地文件缺失和持久化失败应能区分。当前曲目完成一次 URL 重试后仍失败时，播放器停留在失败曲目、保留队列并显示错误；不自动跳曲，用户可以重试或手动下一首。

### PLY-03：第一阶段做短淡入淡出

播放、暂停、恢复和手动切歌采用短淡入淡出。第一阶段不做两首重叠的交叉渐变。过渡不能改变歌曲身份、跳过取消检查或提前触发收集。

2026-10-26：另行批准自动下一首的双通道交叉渐变，具体规则见第 19 节；本条继续约束短暂停、恢复及手动切歌。

2026-10-12 D-C 已采用：短淡入淡出默认开启，在播放设置提供关闭开关；暂停/恢复 150 ms，启动及手动切歌 300 ms，作为集中试听的初始值，尚不代表试听确认。用户音量与过渡增益分别管理，过渡不得改写用户音量。自然结束、进度拖动和静音不新增过渡；停止立即取消。手动切歌先淡出旧曲，再停止并解析/加载新曲。

## 7. 当前差异与开发阶段

以下差异来自本轮静态代码分析，不表示已经运行复现所有问题。文件位置用于制定实施计划；后续动手前重新核实当前代码。

| 当前差异 | 代码入口 | 对应规则 | 阶段 |
| --- | --- | --- | --- |
| 在线条目仍可自动使用本地文件 | `src/renderer/src/stores/player.ts` 的 `resolve` | SRC-01 | A |
| 搜索先加入默认列表，再播放默认列表；本地搜索播放全部结果 | `src/renderer/src/views/SearchView.vue` 的播放入口 | QUE-01、COL-01 | A |
| 目录准入仍依赖已启用音源声明的平台 | `src/main/online/platform-registry.ts` | SRC-02 | A |
| 一个脚本逐档降低后才尝试其他脚本，原平台失败后才跨平台 | `src/main/sources/source-engine.ts`、播放器解析流程 | AUD-01 | B |
| 同版本匹配依赖歌名与歌手完全相同、时长存在，使用首个符合项 | 播放器的 `sameRecording` 和跨平台搜索 | AUD-02 | B |
| 返回音质是解析请求档位，不能当作测得的音频规格 | `SourceEngine.getMusicUrl` 与播放详情 | AUD-03 | B |
| 队列恢复的成功返回与播放失败状态可能不一致 | 播放器恢复流程、`src/renderer/src/App.vue` | QUE-03、PLY-02 | A |
| 下载完成与本地入库缺少统一确认链路 | 下载管理、曲库扫描与 IPC | SRC-04 | C |

阶段 A：统一行为。落实来源独立、目录解耦、单曲试听、统一播放确认与收集、队列恢复反馈、迟到结果失效。先使同一操作在各入口产生一致结果。

阶段 B：统一解析。落实原条目与播放资源分离、档位优先调度、同版本候选、缓存身份、兼容音源选择、有界失败重试和准确音质显示。

阶段 C：完善日常体验。落实下载入库反馈、本地资料补充边界、短淡入淡出与必要界面反馈。保持本地播放器在没有音源时可独立使用。

阶段之间允许按依赖拆分交付；不能为赶进度先引入与规则冲突的临时行为。此处是规划顺序，不是代码任务清单或工期承诺。

## 20. 当前队列手动切歌交叉渐变（2026-10-26）

依据[已批准设计](superpowers/specs/2026-10-26-manual-crossfade-design.md)，独立设置默认关闭，0–12 秒、1 秒步进。仅当前队列的下一首、实际上一曲及点选使用受保护交接；跨队列、历史恢复和内部重试沿用既有路径。

- 目标解析和缓冲期间保持旧曲身份、实时进度和声音；新曲有效播放才提交身份与播放记录。短曲或未知时长也须完成准备后直接交接。
- 连续导航使用待切游标；准备中上一首撤回请求，退回旧曲不重置进度。未发声的随机抽取按顺序归还一次，不加入实际播放历史。
- 手动和自动预约最多共用一个备用通道；可复用同目标自动准备，手动失败不劫持后续自动目标。新请求在已开始的渐变中先完成当前交接，再准备最新目标。
- 准备中暂停或定位取消目标；渐变中暂停冻结双通道，定位保留已提交新曲。停止、新队列、来源变化与无效队列修订取消迟到结果。
- 关闭手动设置时，进行中的渐变立即完成；准备中的选歌转原流程继续执行。自动时长、手动时长和短过渡开关互相独立。
- 准备提示绑定有效请求，失败走既有通知，不污染旧曲媒体错误链。

证据与边界见[开发验收记录](development/2026-10-26-manual-crossfade.md)。人工听感待验。


## 21. A–B、睡眠停止与跨队列渐变（2026-10-26）

依据用户批准的[联合设计](superpowers/specs/2026-10-26-playback-expansion-design.md)，在手动渐变基础上扩展：

- A–B 端点属于当前完整歌曲身份且只在本次会话保留；有限时长、片段至少1秒，到B回A而不增加播放历史。片段外手动定位暂停循环；停止或成功换曲清除；交接失败回滚可恢复旧曲端点，但不能恢复用户在准备期间已清除的端点；清除循环不取消已选歌曲。
- 睡眠保留到点立即停止，新增播完当前曲再停止。后者到点退出A–B，从实际位置播完整首，不单曲重播或自动下一首；未知时长立即停止。暂停保留等待，有效用户选歌取消等待，未到点的计时跨换歌保留。
- 新歌单、曲库、搜索、榜单和公开歌单直接播放使用显式新队列动作。准备阶段保留旧队列、模式、历史、歌词和媒体归属；首次有效playing提交，交接完成前失败回滚旧队列与实时状态。
- 自动恢复、内部重试与历史队列恢复维持既有路径。手动时长沿用0–12秒独立设置，默认关闭；最多两个通道。
- 睡眠到点与incoming playing竞争必须先确定唯一已提交身份，不能出现音频播放新曲而界面保留旧队列。当前队列与跨队列目标即使同歌曲，也属于不同完整意图。
- 队列历史和会话沿用既有串行设置写入，回滚后的最终保存不得被较早保存覆盖，不能撤销同期无关设置。

本节取代第20节中“跨队列一律沿用原流程”的旧范围；历史队列恢复继续排除。验收证据见[开发记录](development/2026-10-26-playback-expansion.md)。人工听感仍待验，开发分支改动尚未发布。

随机交接失败恢复旧曲时，随机导航的当前记录同步对齐旧曲，已发声目标仍保留历史；跨队列回滚不重复当前记录。快速交接后的停止、暂停及重新计时必须移除旧增益曲线，不能因活动曲线重叠中断资源释放。
