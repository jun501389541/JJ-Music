# 歌单批量管理与本地缺失引用汇总（2026-10-24）

两项均由用户选择并确认[具体设计](../superpowers/specs/2026-10-24-playlist-bulk-missing-design.md)，按[本地实施计划](../superpowers/plans/2026-10-24-playlist-bulk-missing.md)完成。

## 普通歌单批量删除

歌单管理 → 批量管理 → 勾选普通歌单或全选当前名称筛选结果 → 删除选中歌单 → 核对名称/数量后确认。

收藏和默认列表的选择框禁用，不参与删除。批量模式点击卡片仅切换选择，不打开或播放；隐藏单个删除按钮。名称筛选变化、退出模式清空选择，一次最多1000个不同普通歌单。主进程严格接收ID数组，不接收路径或原始资料；未知ID、重复ID或任何系统ID使整批拒绝。

在现有mutation队列内一次原子保存全部删除，失败整批回滚。只移除歌单及关联，不删除音频、清空收藏或替换当前播放队列。成功后清理侧栏自定义顺序中的已删除ID，其余顺序保留。若删除已提交但顺序保存/列表刷新失败，明确提示已删除、重启核对、无需重复删除。

本阶段不含批量改名、合并、复制或恢复覆盖。

## 缺失文件检查

歌单管理 → 缺失文件检查 → 检查已保存引用。进入页面不会自动扫描，用户明确点击后检查现有曲库索引与已保存歌单/收藏的本地引用，仅查询存在和文件类型，不读取音频或遍历目录，不调用在线接口，不删除引用。

按本地ID+规范化路径合并重复引用，保留不同来源ID和名称；在线条目排除。显示曲名、歌手、原路径及来源。已存在普通文件只计数；根盘可访问并且路径ENOENT/ENOTDIR才确认缺失。盘不可用、权限/I/O错误、目录而非文件等归为无法确认；UNC网络路径不自动探测。候选缺失错误后再次核对根盘，避免检查途中拔盘被误判。

上限50000个不同本地引用、8个底层stat任务、500条展示结果、每轮30秒等待。为限制来源快照内存，曲库和已保存歌单各最多提取50000条最小本地引用；触及来源或去重容量上限均明确报告不完整。显示问题数超500时只展示前500条，计数仍包含全部已检查结果。取消、离页及超时不提交迟到结果。

系统已开始的stat无法强制中止；共享检查器保留这些未结束任务占用的槽位，新检查等待空闲槽位并同样可取消/超时，因此连续取消/重查不会叠加超过8个底层请求。超时只保留已完成的快照，未完成项不判为缺失。

可勾选最多50条确认缺失项，进入现有候选目录 → 人工核对 → 预览确认的批量重新定位流程。无法确认项不可勾选；同一曲目ID对应多个旧路径时分批处理，以匹配既有修复入口的ID约束。不自动匹配、播放或写入音乐；引用和文件变化由原有重新定位预览/提交再次校验。

## 审查修复

- 检查中拔盘：先用生产bundle复现首次根盘可访问、随后文件/根盘ENOENT仍被当缺失，再增加缺失错误后的在途合并新根盘检查；旧成功缓存不能决定该次缺失。
- 第51首或重复ID拒选：生产UI复现模型已拒绝但原生checkbox仍为勾选。事件结束后明确恢复真实选中状态；普通歌单1000上限同类入口也同步。
- 连续取消的底层请求：先复现取消只结束等待、再次检查会叠加原生stat，再将原生任务槽位跨检查共享、实际完成才释放。仍保持取消和30秒时限。
