# F1 扩展：酷狗、酷我、咪咕榜单

日期：2026-10-24。状态：用户已通过“开始实施”批准。酷狗、酷我及咪咕均已接入；接口证据和边界见对应开发记录。

## 目标与范围

用户要求把现有网易云、QQ榜单继续扩展到其他平台。本设计建议本轮覆盖应用已有的其余三个在线平台：酷狗（kg）、酷我（kw）、咪咕（mg）。沿用现有排行榜页面、标准曲目菜单、收藏和常规队列，不新增账号、脚本榜单协议、第三方API依赖、订阅或定时同步。

现有双平台改动保留在 codex/platform-charts，尚未提交。本批不自动提交、合并、推送、发布或改版本号。

## 方案选择

沿用现有平台目录适配器、ChartsService和页面状态是本次唯一建议方案：它符合已确定的“应用目录提供资料、LX音源只解析播放地址”的分工，能复用请求策略和已有回归。恢复脚本榜单协议会改变已确认分工；另建第三方聚合后端会增加当前项目没有的外部依赖，本轮不采用。

三平台统一纳入开发及验收范围，按各自真实接口进展记录。接口未核实或本轮不可用时，显示独立、可解释的不可用状态，不通过硬编码榜单、第三方中转或假曲目伪装成功，也不默默把未完成的平台记为完成。

## 接口核实和请求边界

设计时只做过初步公开页面检查：酷狗移动JSON地址在网页读取工具中不能正常解析；酷我页面读取超时；咪咕公开页面未返回可读正文。这些结果只说明读取方式未获得契约，不说明平台没有榜单。本轮不据此声称三平台已支持。

实施阶段先检查各平台官网当前公开入口及必要响应，不读取账号或Cookie，不执行下载的网页脚本或第三方音源。每平台首次契约联调最多3个有界请求（可选入口/配置、列表、明确榜单的首页），不自动重试制造通过；如需额外请求，先记录具体缺口及原因。真实网络与离线夹具分开，不把合成结果标为真实兼容。

生产请求沿用固定官方域名、受限重定向、取消、响应体上限、总预算、错误分类及Retry-After。非JSON入口如确有必要，仅解析明确、受大小限制的公开资料，禁止eval及从渲染进程传入任意URL。

## 数据和身份

扩展共享平台配置并由其初始化状态/标签，减少后续平台名单漂移。参数和缓存验证按实际平台榜单ID契约分别设白名单与长度限制，不把现有数字ID校验无条件放宽为任意字符串。

榜单和歌曲身份均包含平台。曲目复用既有平台标准化能力：酷狗保留hash及必要播放信息，酷我保留rid，咪咕保留songId/copyrightId等真实字段，不套用网易或QQ的必填结构。缺少必要身份视为格式错误；合法空榜与损坏响应分别处理。

既有wy/tx缓存键和修订保持兼容；新增平台独立修订，校验并拒绝跨平台或畸形持久化条目。继续使用2MiB榜单缓存总预算及现有清理入口，无用户歌曲/歌单数据迁移，不持久化播放URL。

## 分页、周期和交互

保持每页20首、手动加载、最多500首，播放按钮只覆盖已加载曲目。后页失败保留已有内容，部分首页修复不丢已加载后页，平台切换保留独立状态，旧请求迟到不覆盖新选择。

平台提供可靠周期/版本时携带并核对，变化后需明确刷新并替换旧快照。没有可靠周期时，若能通过一次有界响应获取不超过500个有序曲目ID，则以该ID快照分页，不能用当前日期伪造版本。若既无版本又无法建立稳定快照，则首版只展示可靠的已取得范围并提示后续分页不可用，不直接拼接可能属于不同周期的页面。上游原生页大小不同时由适配器按20首对外切页，并保持单次请求预算和上限，不默认抓取整榜。

页面增加三个平台选项及各自加载/失败/空状态。无需可用音源即可浏览；实际播放仍需现有可用音源，失败沿用播放器规则。封面通过现有平台域名限制处理，取不到不影响榜单内容。

## 验收与交付

1. 每平台记录真实入口、响应字段、所选样本及结果；失败平台逐项保留，不能以离线测试替代真实可用证明。
2. 生产模块离线测试覆盖列表、曲目标准化、ID拒绝、合法空/畸形、分页与上限、未知版本处理、取消、缓存恢复与平台隔离，并确保wy/tx原测试继续通过。
3. 隔离生产Electron页面检查五个平台切换、同ID隔离、部分结果与重试、收藏原生身份、已加载范围及无音源提示；仅HTTP层夹具可注入，不接触日常profile或真实第三方音源。
4. 完整 npm run verify、独立复核、更新README开发状态/产品规则/开发记录，增量GraphFlow同步。实际播放与听感继续独立待验。
5. 若某平台公开接口受限导致未完成，开发记录应明确该平台剩余项，交付总结按已实现、离线通过、真实可用分别描述。
